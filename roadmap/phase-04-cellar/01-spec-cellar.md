## 1. 概要

セラー（ボトル在庫）の画面項目・バリデーション・写真方針を仕様化し、承認後に実装する。コード変更なし。

## 2. 前提条件

- Phase 1 の data-model / api-design / 画面
- Phase 2 基盤
- 写真の数値（サイズ上限）は本仕様か 4-04 で確定し、相互リンク

## 3. スコープ

**対象**

- ボトルのフィールド一式（要件 1.3）
- ステータス 3 種
- 一覧の絞り込み・検索
- 写真 1 枚か複数か（要件は「写真」。複数はノート側。ボトルは **要確認**）
- 飲み切り時の本数

**対象外**

- 飲み頃アラート、在庫金額サマリー（v1.x）
- バーコード
- 実装

## 4. 成果物

- `spec/features/cellar.md`
- spec/README 更新

## 5. 細分化タスク

1. 要件の列を画面項目表にする（必須/任意）
2. 検索・フィルタ仕様
3. ステータス遷移図
4. 写真の枚数・リサイズ後解像度（4-04 と重複しないよう「詳細は photo 節」）
5. 承認 PR `docs: セラー機能仕様を追加`

## 6. 手順

feature-dev Step 1。実装タスク 4-02 を同じ PR に混ぜない。

未決を残すなら表にして承認をブロックする。

## 7. 仕様詳細

必須になりやすい: 銘柄名、種類、ステータス。

任意: 生産者、産地、ヴィンテージ、購入日、価格、場所、本数、保管場所、メモ、写真。

種類は飲酒記録の 7 種と揃えるか、ワイン/ウイスキー等セラー向け細分にするか。**要確認**（揃えた方がフィルタが楽）。

検索: 銘柄名・生産者の部分一致。SQLite `LIKE` は Drizzle でプレースホルダ。大文字小文字は **要確認**。

価格は整数円。小数なしでよい。**要確認**。

## 8. 受け入れ条件

- [ ] 画面・バリデーション・API 対応・エッジケースがある
- [ ] オーナー承認
- [ ] v1.x が混ざっていない
- [ ] 写真の認可方針が security と矛盾しない

## 9. セキュリティ観点

- メモ・銘柄の XSS
- 価格は他人に見えない（全部プライベート）
- アップロードはサーバー検証（詳細 4-04）
