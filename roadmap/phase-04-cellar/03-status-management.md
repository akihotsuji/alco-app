# 4-03 ステータス管理（未開栓/開栓済み/飲み切り）

| 項目 | 内容 |
|---|---|
| フェーズ | Phase 4 セラー管理 |
| ステータス | **未着手** |
| 要件 | ステータス 3 種、一覧フィルタ |
| ソース | Phase 4 ステータス管理 |

## 1. 概要

ボトル状態の遷移と表示を専用に仕上げる。4-02 で enum 保存済みなら、本タスクは UI・フィルタ・遷移ルールとテスト。

## 2. 前提条件

- 4-01、4-02（最低限 status 列）
- 開栓→記録誘導は v1.x なのでボタンだけ出して disabled にしない。**出さない**

## 3. スコープ

**対象**

- 3 ステータスの表示（バッジ）
- 詳細からの変更（確認の有無は仕様）
- 一覧フィルタ
- 不正値を Zod で拒否

**対象外**

- 自動で飲み切りにするロジック（本数連動は **要確認**。やるなら仕様にアルゴリズム）
- 通知

## 4. 成果物

- ステータス変更 API（PATCH の一部でも可）
- UI
- テスト: 不正 enum 400、他人 404

## 5. 細分化タスク

1. 遷移を全許可するか（飲み切り→未開栓の戻し）**要確認**
2. バッジ色はトークン（成功/警告/muted）
3. フィルタ UI
4. テスト
5. cellar.md に遷移図を同期

## 6. 手順

ブランチ: `feature/bottle-status`（4-02 と分ける場合）。小さく済むなら 4-02 に含めてロードマップ 2 チェックを同じ PR で更新してもよいが、workflow は 1 関心事。ステータスが CRUD の一部なら 4-02 完了時に本ファイルの手順を実施済みと記録する。

## 7. 仕様詳細

提案（要確認）:

- どの状態へも変更可（誤操作修正）
- 飲み切りは一覧デフォルトから外し「飲み切りを含める」トグル
- 開栓日を別カラムで持つかは data-model。無ければメモ運用

## 8. 受け入れ条件

- [ ] 3 状態を設定・フィルタできる
- [ ] 不正ステータスを保存できない
- [ ] 認可テスト
- [ ] spec 同期

## 9. セキュリティ観点

- status を文字列自由入力にしない（enum）
- フィルタで他ユーザー行が混ざらない
