# 5.5-01 実機検証の準備

| 項目 | 内容 |
|---|---|
| フェーズ | Phase 5.5 実機検証・機能安定化 |
| ステータス | 未着手 |
| 目的 | Phase 5完了後、同じ条件で再現・比較できる検証基準を作る |

## 前提条件

- Phase 5のDoDとCIが完了している
- Phase 5完了コミットをdev環境へデプロイできる
- オーナーの主利用実機でdev URLを開ける

## 成果物

- 検証対象のコミットSHAとdevデプロイ日時
- 実機マトリクス（機種名は任意、OS、ブラウザと版、PWA / ブラウザ、接続条件）
- テストアカウントとテストデータの準備記録。シークレットや実データは書かない
- 実行結果を記録する `spec/qa-phase-5-5.md`。着手時に作り、各検証の結果と関連Issueだけを追記する
- 写真処理の基準値（初回 / 2回目、切り抜き、ラベル認識、アップロード、全体）

## 手順

1. 最新mainでlint / typecheck / test / buildを実行する
2. リモートD1の未適用マイグレーションを確認し、[spec/dev-deploy.md](../../spec/dev-deploy.md) に従ってdevへデプロイする
3. テスト用の記録、ボトル、ノート、写真を用意する。日常利用データは証跡に使わない
4. 主利用実機でログインし、カメラ / 写真ライブラリ、Cookie、R2配信、Workers AIが利用できることを確認する
5. ブラウザの時計で体感時間を断定せず、アプリの計測値または再現動画の時刻から基準値を取る
6. `spec/qa-phase-5-5.md` に成功 / 失敗 / 未実施と理由を残す

## 実機情報の最小項目

| 項目 | 例 |
|---|---|
| OS | iOS 18.x / Android 16 |
| ブラウザ | Safari / Chrome と版 |
| 起動形態 | ブラウザ。PWAはPhase 6で別記録 |
| 接続 | Wi-Fi / モバイル |
| 省電力 | ON / OFF |
| アプリ版 | コミットSHA |

## 計測ルール

- 初回モデル取得とキャッシュ済みを分ける
- 写真と入力条件を固定してBefore / Afterを比べる
- 少なくとも3回測り、中央値と失敗回数を記録する
- 写真処理では切り抜き成功だけでなく、背景残り・対象欠け・長方形フォールバックも記録する
- ラベル認識では所要時間と、各フィールドが正しい / 誤り / 未取得のどれかを記録する
- 閾値は測定前に「速く見せるため」変更しない

## 受け入れ条件

- [ ] Phase 5完了コミットがdevへデプロイ済み
- [ ] 主利用実機の検証条件とテストデータが記録済み
- [ ] `spec/qa-phase-5-5.md` の記録欄が用意されている
- [ ] Issue #48のBefore値を取れる写真と計測条件が用意されている
- [ ] 証跡にシークレット・実利用の個人データが含まれない

## リスク

- dev環境にはPhase 7の本格バックアップがない。破壊的な確認はテストデータだけで行う
- モバイルブラウザのバックグラウンド化で計時が歪むため、計測中は画面を前面に保つ
