## 実施方法

台本どおりの正常系だけでなく、戻る、連打、通信切断、再試行、入力途中の画面離脱、写真撮り直しを含む探索を行う。チェック結果は`spec/qa-phase-5-5.md`へ記録し、問題ごとに [実機QAテンプレート](../../.github/ISSUE_TEMPLATE/device-qa.yml) で1件ずつ起票する。

最低限、主利用実機1台で全項目を行う。別OSの端末が利用できる場合は差分を記録するが、iOS / Android両方のPWA最終確認はPhase 6-05で行う。

## Issue化の判定

| 観測 | 扱い |
|---|---|
| 仕様と実装が違う | バグIssue。正本の箇所を記載 |
| 仕様どおりだが利用上問題 | 仕様変更候補Issue。コードより先に設計変更 |
| 一度だけで再現しない | 証跡と条件を記録し、追加観測。原因を断定しない |
| 既存Issueと同じ | 新規起票せず、端末条件・再現率・証跡を既存Issueへ追加 |
| セキュリティCritical / High | 公開Issueへ機微情報を書かず、規約に従って最優先対応 |

## 受け入れ条件

- [ ] 全項目が成功 / 失敗 / 未実施のいずれかで記録され、未実施には理由がある
- [ ] 失敗は1問題1Issueで、最小再現手順と証跡がある
- [ ] 「遅い」は工程と時間、「時々」は試行回数と失敗回数で表している
- [ ] 実データ・シークレット・個人情報を証跡に含めていない
- [ ] 新規Issueが優先度と対象Phaseを持ち、重複が整理されている
