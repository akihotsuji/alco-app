| 項目 | 内容 |
|---|---|
| フェーズ | Phase 7 本番リリース |
| ステータス | **未着手** |
| 要件 | 本番稼働、dev 分離 |

## 1. 概要

リリース当日に人が飛ばさない項目を 1 枚に固定し、実際に実施する。skill `release` もここで完成させてよい。

## 2. 前提条件

- 7-01〜7-07 の成果（監査ゼロ、バックアップ、パイプライン）
- 6-05 の実機結果

## 3. スコープ

**対象**

- `spec/release-checklist.md` の作成
- 初回本番リリースでの実施（チェックを埋める）
- `.cursor/skills/release/SKILL.md`

**対象外**

- 機能追加
- マーケティング告知

## 4. 成果物

- `spec/release-checklist.md`
- 実施済みの記録（日付、実施者）。秘密なし
- release スキル

## 5. 細分化タスク

1. チェックリスト草案（下記を正に近い形で spec へ）
2. スキルに「実行順、ロールバック参照」
3. 本番デプロイ実施
4. 実機スモーク
5. チェックを `[x]` にする（個人情報を書かない）

## 6. 手順

チェックリスト実施順の提案:

1. CI グリーン
2. セキュリティ監査レポート合格
3. 本番 secret 投入済み
4. 本番 migrate
5. 本番デプロイ（承認付き workflow）
6. `/api/health`
7. サインアップまたはログイン（本番ユーザー。dev と混ぜない）
8. 記録 1 件、ボトル 1 件、ノート 1 件
9. 写真が表示される（自分だけ）
10. PWA 追加（任意だが DoD 的には推奨）
11. バックアップジョブを手動 1 回
12. ロールバック手順を声に出して確認（7-09）

失敗したらデプロイを進めない。

## 7. 仕様詳細

spec に含める節:

- 事前条件
- デプロイ
- 機能スモーク
- セキュリティ（R2、headers）
- 監視が生きている
- 完了条件
- ロールバックリンク

## 8. 受け入れ条件

- [ ] `spec/release-checklist.md` がある
- [ ] 初回リリースで実施した
- [ ] 本番 URL でアプリが動く（Phase 7 DoD）
- [ ] spec/README 更新
- [ ] スキルがある

## 9. セキュリティ観点

- チェックリストにトークンを書かない
- 本番に dev のテストアカウントパスワードを使い回さない
