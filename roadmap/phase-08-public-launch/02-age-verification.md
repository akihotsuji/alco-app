# 8-02 年齢確認（20歳以上）フロー

| 項目 | 内容 |
|---|---|
| フェーズ | Phase 8 一般公開準備 |
| ステータス | **未着手** |
| 要件 | 一般公開時に 20 歳以上の年齢確認 |
| ソース | Phase 8 年齢確認 |

## 1. 概要

酒類関連アプリとして、20 歳未満が本機能を使えないようにする。本人確認書類までは求めない想定だが、強度は **要確認**。

## 2. 前提条件

- 8-01 の禁止条項と整合
- 認証基盤（Better Auth）

## 3. スコープ

**対象**

- 登録時または初回アクセス時の確認 UI
- サーバー側フラグ（未確認なら API を 403 または専用 451 相当。ステータスは **要確認**。既存は 401/404 方針と矛盾しうる。未確認は機能 API を 403 で「年齢確認が必要」と汎用化し、ユーザー列挙しない）
- 拒否時の画面（20 歳未満は登録不可）

**対象外**

- eKYC、免許証アップロード（やるなら別プロジェクト。R2 に身分証は置かない推奨）
- 地域ごとの飲酒年齢の自動切替

## 4. 成果物

- 仕様 `spec/features/age-verification.md`
- UI + サーバー強制
- テスト: 未確認で drink-logs が書けない

## 5. 細分化タスク

1. 強度を決める（チェックボックス vs 生年月日）
2. 生年月日を持つなら保持方針（PP 同期）
3. 実装
4. テスト
5. 監査

## 6. 手順

チェックボックスのみは弱いが個人公開の第一歩には使われる。ロードマップは「フローの実装」。**推奨: 生年月日を入力し、当日 JST で 20 歳以上をサーバー計算。** クライアント判定だけは不可。

```powershell
git checkout -b feature/age-gate
```

公開エンドポイント（確認 API）は仕様承認が必要。

## 7. 仕様詳細

- 20 歳の定義: 満 20 歳（誕生日の前日終了後。日本の年齢計算）。**要確認** 法務
- 一度確認したらセッションだけでなく user に保存
- 既存個人ユーザー（オーナー）の移行: 管理フラグでスキップか、一度だけ確認。**要確認**

## 8. 受け入れ条件

- [ ] 未確認では記録・セラー・ノートが使えない
- [ ] サーバー強制がある
- [ ] テストがある
- [ ] PP と項目が一致
- [ ] DoD / 監査

## 9. セキュリティ観点

- 生年月日は要配慮になりうる。ログ禁止
- クライアントの `isOver20: true` を信じない
- 身分証を安易に集めない
