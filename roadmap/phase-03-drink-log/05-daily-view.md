# 3-05 日別ビュー（一覧・合計・編集・削除）

| 項目 | 内容 |
|---|---|
| フェーズ | Phase 3 飲酒記録 |
| ステータス | **未着手** |
| 要件 | 日別: 杯数・純アルコール量。記録の編集・削除 |
| ソース | Phase 3 日別ビュー |

## 1. 概要

指定日（デフォルト今日、JST）の記録一覧と合計。編集・削除。これが日常画面の本体になる可能性が高い。

## 2. 前提条件

- 3-02 の作成 API
- 1-06 の日付境界（**Asia/Tokyo**。2026-08-13 確定）
- 共通レイアウトの記録タブ

## 3. スコープ

**対象**

- GET 一覧（from/to または date クエリ）
- PATCH / DELETE
- UI: 日付切替、合計、リスト、編集フォーム、削除確認
- 空状態（休肝の日）

**対象外**

- 週月グラフ（3-06）
- 他ユーザーの日次

## 4. 成果物

- API GET/PATCH/DELETE
- 日別画面
- テスト: 自分の行だけ、他人は 404、削除確認

## 5. 細分化タスク

1. GET を日付でフィルタ（サーバー側。TZ は JST の日の始まり〜終わりを UTC に変換）
2. PATCH は Zod 部分更新。alcohol_g 再計算
3. DELETE は id+userId
4. UI
5. 認可テスト 404
6. 監査

## 6. 手順

ブランチ: `feature/drink-log-daily`

日付処理は shared に `jstDayRange(isoDate)` を置きテストする（計算以外のロジックもテスト対象）。

削除は誤操作が多い。仕様の確認ダイアログに従う。

```powershell
pnpm test && pnpm lint && pnpm typecheck
```

## 7. 仕様詳細

- 合計杯数 = 行数（1 行 1 杯）
- 合計 g = 行の計算値合計
- 編集で種類を変えたときプリセット上書きかは 3-01 に従う
- 存在しない id と他人の id はどちらも 404

**要確認**: 日付ピッカーの UX（前日翌日ボタン必須か）

## 8. 受け入れ条件

- [ ] 当日の一覧と合計が見える
- [ ] 編集・削除ができる
- [ ] 他ユーザー 404 テスト
- [ ] 空状態がある
- [ ] DoD 5 項

## 9. セキュリティ観点

- 削除条件は id 存在確認だけにしない
- メモ編集も XSS なし
- クエリ `from` `to` を Zod で ISO 日付に制限（SQL インジェクション不可でも異常値で全件取得しない）

- JST と UTC のオフセットで「今日」がずれる
- 一覧をクライアントフィルタだけにすると全件送信になる。必ず期間指定
