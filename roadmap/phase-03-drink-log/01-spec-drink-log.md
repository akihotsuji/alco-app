## 1. 概要

飲酒記録機能の詳細仕様を書き、オーナー承認後に初めて実装する。本タスクではアプリケーションコードを変更しない。

## 2. 前提条件

- Phase 1 の画面・計算・API・データモデルが承認済み
- feature-dev スキルに従う

## 3. スコープ

**対象**

- 画面項目、バリデーション、計算、エッジケース、API 対応表
- マイドリンク、日別、週/月の仕様の親ドキュメント（詳細は後続タスクからもリンク）

**対象外**

- 実装、テストコード
- セラー連携（v1.x）
- 目標設定（v1.x）

## 4. 成果物

- `spec/features/drink-log.md`
- `spec/README.md` の features 行を「作成済み」に更新

## 5. 細分化タスク

1. 既存 spec から転記し、矛盾を洗い出す
2. 画面ごとに項目表を書く
3. バリデーションとエラーメッセージ（日本語）
4. エッジケース（日付変更、削除、プリセット変更後の過去ログ）
5. オーナー承認を待ってから 3-02 以降に進む旨を明記

## 6. 手順

1. `spec/features/drink-log.md` を作成。推奨見出し:

- 目的 / 対象外
- 用語（グラス、休肝日、マイドリンク）
- 画面項目
- バリデーション
- 計算（1-06 へのリンク + 差分なしの宣言）
- API
- エッジケース
- 未決（要確認）を残さない。残すならリスト化して承認ブロックにする

2. PR: `docs: 飲酒記録の機能仕様を追加`。実装 PR と混ぜない。

3. 承認後に 3-02 のブランチを切る。

## 7. 仕様詳細

必ず含める（要件由来）:

- 種類 7、量 ml、度数、日時デフォルト現在、任意メモ
- 種類選択で要件 1.2 のデフォルト量・度数を投入し、記録ごとに修正できる
- 日付境界は Asia/Tokyo（保存 UTC）
- 式 `量 × 度数 / 100 × 0.8`
- マイドリンク 1 タップ
- 日別杯数・純アルコール
- 週/月グラフ、休肝日数

エッジケース例:

- 日付を跨いだ編集（昨日の記録を今日に変える）
- 未来時刻
- メモの XSS（テキスト表示）
- 同時タップで二重 POST（idempotency は **要確認**。MVP はボタン disable で可）
