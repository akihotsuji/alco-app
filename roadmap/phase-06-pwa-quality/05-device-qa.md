# 6-05 iOS Safari / Android Chrome 実機動作確認

| 項目 | 内容 |
|---|---|
| フェーズ | Phase 6 PWA・品質 |
| ステータス | **未着手** |
| 要件 | 対応デバイス第一、PWA ホーム追加 |
| ソース | Phase 6「実機動作確認と表示崩れ修正」 |

## 1. 概要

エミュレータでは分からないセーフエリア、PWA 追加、入力ズーム、100vh 問題を実機で潰す。Phase 6 DoD の「両方でアプリとして起動」。

## 2. 前提条件

- 6-01 PWA
- 3-07 の dev URL またはトンネル
- オーナーの iPhone / Android（エージェントは実機を持てない。チェックリストを用意しオーナーが実施）

## 3. スコープ

**対象**

- 両ブラウザでの主要導線
- ホーム画面追加後の standalone
- 表示崩れ修正 PR
- チェックリスト（後で release-checklist に統合可）

**対象外**

- 古い OS 全部
- 折りたたみ端末の特殊ケース
- PC の完全最適化（崩れない程度は見る）

## 4. 成果物

- `spec/qa-devices.md` または Phase 6 チェックリスト
- 修正コミット
- DoD 確認の記録（日付、OS 版は任意。個人情報は機種名程度）

## 5. 細分化タスク

1. チェックリスト作成（下記）
2. オーナー実施
3. バグを issue または PR で修正
4. PWA 追加手順を README に（iOS: 共有 → ホーム画面に追加）

## 6. 手順

エージェント:

1. チェックリストを書く
2. safe-area、`dvh`、入力 16px、横向き、ノッチを先にコードで潰せるものは潰す
3. オーナー結果待ち
4. 再現可能な崩れを直す

オーナー:

- iOS Safari: ログイン、1 タップ記録、一覧、セラー写真、ノート、ホーム追加
- Android Chrome: 同様 + インストールバナーがあれば試す

## 7. 仕様詳細

チェック項目案:

- [ ] ログインできる
- [ ] 記録保存が 1 秒体感
- [ ] 下部タブがホームバーと重ならない
- [ ] キーボードで保存ボタンが使える
- [ ] 写真ピッカーが開く
- [ ] standalone でブラウザ UI が消える
- [ ] 戻るジェスチャでアプリが死なない（Android）
- [ ] 100 件でも一覧がスクロールできる

**要確認**: サポート最小バージョン（例 iOS 17+ / Android Chrome 最新）

## 8. 受け入れ条件

- [ ] iOS と Android の両方でホーム追加起動（Phase 6 DoD）
- [ ] ブロッカーな崩れがゼロ
- [ ] 修正が lint/test 済み
- [ ] 手順が README にある

## 9. セキュリティ観点

- 実機のスクリーンショットに個人の飲酒ログ実データが PR に入らないようぼかす
- 社内 Wi-Fi のプロキシ等で Cookie が落ちないかは個人利用では無視可

## 11. リスク・注意点

- iOS PWA の Cookie 永続（ITP）。ログインが飛ぶなら session 日数を Better Auth 設定で調整。**要確認**
- `wrangler dev` は LAN 公開が必要な場合あり。dev デプロイ URL の方が楽
