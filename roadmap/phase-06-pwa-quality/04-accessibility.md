# 6-04 アクセシビリティ最低限対応

| 項目 | 内容 |
|---|---|
| フェーズ | Phase 6 PWA・品質 |
| ステータス | **未着手** |
| 要件 | タップ領域、コントラスト、フォームラベル。Lighthouse a11y 目安 80 |
| ソース | Phase 6 アクセシビリティ |

## 1. 概要

WCAG の完全準拠ではなく、スマートフォンで困らない最低限。ラベルなし入力、薄い灰色文字、小さすぎるタブを潰す。

## 2. 前提条件

- 1-03 のコントラスト方針
- 主要画面が揃っている

## 3. スコープ

**対象**

- タップ領域 44x44px 目安（タブ、アイコンボタン）
- コントラスト 4.5:1（本文）
- すべての入力に label（placeholder だけにしない）
- ボタンの accessible name
- フォーカス可視化（キーボード。モバイルでも外部キーボード）
- Lighthouse a11y 80+

**対象外**

- スクリーンリーダー全フローの専門監査
- 多言語
- モーション低減の高度な対応（可能なら `prefers-reduced-motion` でグラフアニメを切る）

## 4. 成果物

- UI 修正
- 可能なら eslint-plugin-jsx-a11y は Biome と重複しうるので **要確認**。Biome の a11y ルールを有効化
- 計測メモ

## 5. 細分化タスク

1. Lighthouse a11y で違反リスト
2. フォーム総点検（ログイン、記録、ボトル、ノート）
3. タブとアイコンボタンのヒット領域
4. 色だけに依存したステータス（バッジに文字も）
5. 再計測 80+

## 6. 手順

Chrome DevTools Lighthouse → Accessibility。手動:

- ズーム 200% で折れない（最低限）
- 削除確認がボタンの名前で分かる

ブランチ: `feature/a11y-baseline`

## 7. 仕様詳細

- エラーは `aria-invalid` とテキスト
- モーダルにフォーカストラップ（shadcn Dialog が提供するはず。自作シートは確認）
- 星評価はラジオグループかスライダーで名前付け

## 8. 受け入れ条件

- [ ] a11y 目安 80+（Phase 6 DoD）
- [ ] 主要フォームにラベル
- [ ] コントラスト不足を意図的に残していない
- [ ] テスト・lint パス
- [ ] 監査（a11y と XSS は別。innerHTML を a11y 目的で使わない）

## 9. セキュリティ観点

- `aria` のために HTML 文字列結合しない
- フォーカスリングを `outline-none` で消したままにしない
