## 1. 概要

毎日の記録とサマリーの前提となる数値ルールを `spec/features/alcohol-calculation.md`（または data-model）へ転記する。デフォルト量・度数と日付境界（Asia/Tokyo）は 2026-08-13 に要件へ FIX 済み。残る未決は丸めと入力上限。

## 2. 前提条件

- 要件の式: `量(ml) × 度数(%) / 100 × 0.8`
- 種類 enum: ワイン / ビール / ウイスキー / 日本酒 / 焼酎 / カクテル / その他
- デフォルト量・度数は [spec/01-requirements.md](../../spec/01-requirements.md) 1.2 の表（2026-08-13 確定）
- 量・度数は記録ごとに修正できる

4. PR: `docs: 純アルコール量とグラスプリセットを確定`

## 7. 仕様詳細

### 式

```
alcohol_g = volume_ml * abv_percent / 100 * 0.8
```

0.8 はエタノール比重の近似（要件どおり）。変更しない。

### 丸め（提案・要確認）

- 保存: 小数第 2 位まで（または IEEE の number のまま表示時だけ丸める）
- 表示: 小数第 1 位
- 合計: 各行を丸めず合算してから表示丸め（推奨。誤差が少ない）

### デフォルト表（2026-08-13 確定）

種類選択時に下表を投入する。**量・度数は記録ごとに修正できる**（手入力または量チップ）。保存するのはその記録の値。

| 種類 | デフォルト量 (ml) | 量チップ例（任意） | デフォルト度数 (%) |
|---|---|---|---|
| ワイン | 125 | 125 / 150 | 12 |
| ビール | 350 | 200 / 350 / 500 | 5 |
| ウイスキー | 30 | 15 / 30 / 60 | 40 |
| 日本酒 | 180（1合） | 90 / 180 | 15 |
| 焼酎 | 60 | 30 / 60 / 90 | 25 |
| カクテル | 120 | 60 / 120 / 200 | 15 |
| その他 | なし（手入力必須） | | なし（手入力必須） |

記録単位はグラス（1杯）が原則。ボトル丸ごと（750ml 等）を 1 記録にするかは残 **要確認**（やるなら量の手入力で足りる）。

### バリデーション（提案・要確認）

- volume_ml: 整数 1〜5000
- abv_percent: 0.1〜100、小数 1 桁まで（0% は酒として無意味なので 0.1 起分か、0 許容か **要確認**）
- drunk_at: 未来日時をどこまで許すか（数分の時計ズレ vs 翌日予約）

### 日付境界・休肝日（2026-08-13 確定）

- 日時の保存は UTC
- 表示・日次集計・「その日」の帰属・休肝日判定は **Asia/Tokyo** のカレンダー日
- その JST 日に drink_logs が 0 件なら休肝日
- 0g だが記録がある（誤入力）は休肝にしない

### マイドリンク

- 保存するのは name + type + volume + abv
- 1 タップ時は **その時点のプリセット値をログへコピー**（後でプリセットを変えても過去ログは不変）

## 9. セキュリティ観点

- 計算は信頼できる shared 関数。クライアント値 `alcohol_g` を API が信じない（サーバー再計算）
- 極端な値でグラフや整数オーバーフローを起こさないよう Zod で上限

## 11. リスク・注意点

- 焼酎 60ml は水割り・ロックの原酒目安。ロック多めは記録時に 90ml へ直せばよい
- 度数 0 と休肝日の定義が紛らわしい（残 要確認）
- 複数タイムゾーンは個人利用では不要。保存 UTC / 集計 JST を守らないと週サマリーがずれる
