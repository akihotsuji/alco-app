# 1-02 主要画面のワイヤーフレーム

| 項目 | 内容 |
|---|---|
| フェーズ | Phase 1 設計 |
| ステータス | **未着手** |
| 要件 | 最短タップで記録、モバイル第一 |
| ソース | Phase 1「主要画面のワイヤーフレーム（ホーム、飲酒記録入力、セラー一覧/詳細、ノート一覧/詳細/作成）」 |

## 1. 概要

主要画面の要素配置・優先順位を合意する。ピクセルパーフェクトなビジュアルではなく、**何がどの順で並ぶか**。Figma 必須ではない。Markdown の箱図、draw.io、手書き写真のいずれでもよい（**要確認**: ツール）。

## 2. 前提条件

- 1-01 の画面一覧（[spec/screens.md](../../spec/screens.md)）。5 タブ確定済み
- `image/image.png` は無関係なポートフォリオ UI。参考にしない

## 3. スコープ

**対象（ロードマップ明示）**

- ホーム
- 飲酒記録入力
- セラー一覧 / 詳細
- ノート一覧 / 詳細 / 作成

**対象外**

- 全画面の高忠実度モック
- デザインシステム（1-03）の色・フォント確定（ワイヤーはグレースケールで可）
- 実装

ログイン画面は「主要」に含まれないが、1 枚あると Phase 2 が楽。任意。

## 4. 成果物

- `spec/wireframes.md`（テキストワイヤー）および/または `spec/wireframes/` 配下の図
- 各画面の「初回表示で見える情報」「主アクション（1 個）」「二次アクション」

## 5. 細分化タスク

1. ツールを決める（テキストでも可）
2. 記録入力を最初に描く（UX 最重要）
3. ホーム、セラー、ノートの順で描く
4. タップ数を数える（記録完了まで）
5. オーナーレビュー → 修正 → 承認

## 6. 手順

1. スマートフォン幅（390px 想定）で、上から:

- ステータスバー相当は描かない
- ヘッダー（タイトル + 右アクション）
- コンテンツ
- 下部タブ（固定）

2. 記録入力の合格ライン案（**要確認**）:

- マイドリンクがあれば **1 タップで保存**（確認ダイアログなし、または軽いトーストのみ）
- マイドリンクなし: 種類 1 タップ → プリセット量 1 タップ → 保存 1 タップ（度数は種類デフォルトのまま）

3. 各ワイヤーに注記:

- 空状態（ボトル 0 本など）
- エラー（保存失敗）
- ローディング

4. レビュー PR: `docs: 主要画面のワイヤーフレームを追加`

## 7. 仕様詳細

### ホーム（草案）

- 今日の純アルコール量合計（g）と杯数
- 休肝日かどうかの表示（記録 0 なら休肝）
- 主ボタン: 「記録する」
- 直近のマイドリンク 2〜4 個（1 タップ記録）
- 週の簡易バー（詳細はサマリーへ）

### 飲酒記録入力（草案）

- 種類チップ（横スクロール可）: ワイン / ビール / ウイスキー / 日本酒 / 焼酎 / カクテル / その他
- 量プリセット + カスタム ml
- 度数（デフォルト編集可）
- 日時（デフォルト現在）
- メモ（任意、後回しで折りたたみ可）
- 保存（画面下部の固定ボタン、親指が届く）

### セラー一覧 / 詳細（草案）

- 一覧: サムネ、銘柄、ステータス、検索、種類/ステータスフィルタ
- 詳細: 写真、属性、ステータス変更、このボトルのノートへのリンク（Phase 5）

### ノート一覧 / 詳細 / 作成（草案）

- 一覧: 銘柄、評価、日付
- 作成: ボトル選択、日付、4 テキスト、評価ステッパー、写真追加
- 詳細: 読み専用 + 編集入口

**要確認**

- 記録入力はフル画面か、ボトムシートか
- ホームの「1 タップ記録」は undo を何秒出すか

## 8. 受け入れ条件

- [ ] ロードマップ記載の画面がすべてカバーされている
- [ ] オーナー合意（Phase 1 DoD）
- [ ] 記録の最短タップ数が数字で書いてある
- [ ] 空状態が考慮されている
- [ ] 実装担当が迷わない粒度（「カードが並ぶ」まで。色は 1-03）

## 9. セキュリティ観点

- ワイヤーにダミー個人情報を実データで載せない
- 他ユーザーのボトルがチラ見えする「発見」UI は作らない（完全プライベート）
