# 友達・近況共有（friends-social）

友達限定の近況フィード。招待リンク／QRで申請し、相互承認した相手にだけ、記録・セラー登録・開栓の共有を見せる。

- 状態: **初版実装**（指示書 2026-09-20。記録統合は #171 到達後に接続）
- 画面の正本: [screen-designs/13-friends.md](../screen-designs/13-friends.md)。設定の追加行は [06-settings.md](../screen-designs/06-settings.md)
- 列: [data-model.md](../data-model.md) 6.15。API: [api-design.md](../api-design.md) 4.12
- プッシュ通知: 申請・承認・リアクションのお知らせを、オンにした端末へ汎用文で届ける（[web-push.md](web-push.md)。2026-09-23）
- 対象外: 返信、コメント、DM、独立投稿、リポスト、ハッシュタグ、ユーザー検索、連絡先同期、公開フォロー、外部SNS、新規投稿のプッシュ、競争、ポイント

## 1. 公開権限

受信対象は共有確定時の有効 `friendship_epochs` を `social_post_recipients` に固定する。閲覧は「本人、または受信行があり世代が現在有効、双方未ブロック、投稿と依存元が有効」。編集で受信者を増やさない。

友達成立日・飲酒日ではなく、共有のサーバー確定順。解除後の再承認で旧投稿は復活しない。

権限外と未存在は同じ 404。元のログ／ボトル API への友達アクセスは不可。共有セラー権限は付与しない。

## 2. 共有

設定「記録時の『友達に共有』を最初からオンにする」（既定 true、サーバー保存）。各操作のスイッチは設定を書き換えない。友達 0 人では共有不可の説明だけ出し、個人保存は可能。友達用の別名入力やプロフィール行は共有・招待・申請の前提にしない。

通常編集は未共有のまま。共有済みは許可項目の変更を追従（`published_at` / 受信者 / リアクション維持）。取消は投稿・反応・関連通知を削除し、元記録は残す。再共有は新しい `operationKey` の新規イベント。

公開項目はホワイトリスト投影のみ。量・アルコール量・価格・店名・座標・保管場所・個人メモ・認証名・メールは返さない。

保存成功＋共有失敗は「記録は保存しました。友達への共有に失敗しました」。同じ元 ID と操作キーで共有だけ再試行する。

## 3. リアクションと通知

マスタ 7 種（`like` / `delicious` / `want_to_try` / `surprised` / `celebrate` / `cheers` / `curious`）。API は DB の有効行を返す。1 人 1 投稿 1 種。自分の投稿には付けられない。一覧は 1 つの操作ボタンと集計だけを出し、種類の選択はシートで行う。詳細は従来どおり種類を並べてよい。

通知は `friend_request` / `friend_accepted` / `reaction` のみ。新規投稿通知は作らない。本文の名前は表示時に現在のアカウント表示名から組み立てる。履歴本文の一括再生成はしない。

未読数（`read_at` が空の本人宛て通知）はヘッダー F2 のバッジに加え、ホーム画面に追加したアプリのアイコンにもバッジで出す（[pwa.md](pwa.md) 6.2）。件数だけで本文は出さない。ログアウト・アカウント削除で消す。

通知が新しく未読になったとき（新規、または既読が未読に戻ったとき）、受信者がプッシュをオンにした端末へ送る（[web-push.md](web-push.md)）。ロック画面は「酒のしおり」と種別ごとの汎用文だけで、名前・お酒・リアクションの種類・写真は出さない。ペイロードは種別と未読数だけで、SW がアイコンのバッジも更新する。許可は設定 S23 または通知画面 N1 の操作でだけ求める。新規投稿のプッシュは送らない。

## 4. プロフィール

- 公開 DTO の `nickname` は互換のため残し、値は現在の `user.name`（trim。空なら「ユーザー」）
- `social_profiles` 行がなくても招待・申請・承認・共有ができる。行の自動作成は upsert し、既存の画像・色・関係を上書きしない
- `profileCompleted` は互換のため残す。値は「友達機能を使える」であり、名前やアイコンの追加入力必須を表さない（常に true）
- `PATCH /api/social/me` の `nickname` は旧クライアント互換で受け取るが、アカウント表示名にも友達専用名にも書き込まない。色・アイコンモードだけ更新する
- アイコンは任意。未設定・画像失敗はワイン君（既定色 `#8E2F3C`）。名前の保存でアップロード画像を外さない

## 5. 招待リンク

形式は `/friends/join#t=` のまま。ブラウザで開いたときは「ログインして続ける」と「招待リンクをコピー」を出す。コピー後は「ホーム画面から酒のしおりを開き、友達 → 友達を追加で貼り付けてください」。PWA 内の友達一覧と空フィードから貼り付けフォームへ進める。貼り付けや URL 読み込みだけでは申請しない。

トークンは同一コンテキストの一時保存に残し、ハッシュを消しても受信した URL を再構築できる。新しい URL が古い保存より優先。申請成功・無効確定では破棄し、通信失敗では再試行のため残す。ログアウト後に前ユーザーの招待を自動申請しない。

インストール済みなら必ず PWA が開くとは限らない（特に iOS ホーム画面）。`scope` / `start_url` は既に `/`。未対応の manifest フィールドで強制起動をうたわない。

## 6. 申請・承認の完了

API 成功後に受信招待の一時保存を消し、関連キャッシュを無効化し、「友達申請を送りました」または「○○さんと友達になりました」を出して `navigate("/", { replace: true })` する。失敗時は遷移しない。

## 7. アカウント削除

退会バッチでプロフィール・アバター R2・投稿・反応・友達・申請・招待・通知・プッシュの購読を既存フローに載せる（購読は `user` の CASCADE）。アバターの R2 は `account_deletion_photo_tasks` で再試行する。
