# 登録の共通識別項目・撮影日・場所・連続導線

飲酒記録・セラー登録・テイスティングノート登録の **共通契約**。画面ごとのぶれをなくし、AI 読取と手入力の役割を揃える。

- 状態: **本 PR で追加**（オーナー依頼を実装承認とみなす）
- 個別機能の正本: [drink-log.md](drink-log.md)、[cellar.md](cellar.md)、[tasting-note.md](tasting-note.md)
- 画面: [03-log.md](../screen-designs/03-log.md)、[04-cellar.md](../screen-designs/04-cellar.md)、[05-notes.md](../screen-designs/05-notes.md)
- 列: [data-model.md](../data-model.md) 6.1 / 6.3 / 6.4
- API: [api-design.md](../api-design.md) 4.3 / 4.5 / 4.6

---

## 1. 目的

3 つの登録画面で、ラベルから分かる識別項目を同じ欄・同じ AI 読取にする。画面固有の＋α（量・度数、保管場所、香り・色味）だけを分ける。飲酒記録の保存後に、同じ内容でノートへ進める。飲酒記録には店名と現在地を残し、日別の「その日いた場所」や記録フォームから地図を開ける。

---

## 2. 共通識別項目

UI ラベルは全画面で次で統一する（セラーの「銘柄名」は **品名**、「産地」は **生産国**、「ビンテージ」は **ヴィンテージ**）。

| UI | 列（記録 / ノート） | 列（セラー） | 入力 | AI |
|---|---|---|---|---|
| 品名 | `drink_name` | `name` | 記録は任意。ノートはボトル未選択時必須。セラーは必須 | 空欄、または直前の AI 値は再読取で上書き |
| 品種 | `variety` | `variety` | 任意 ≦100 | 同上。ラベル表記または確認済み商品資料があるときだけ。代表品種の推測では埋めない |
| ヴィンテージ | `vintage` | `vintage` | 任意。1800〜2100 / 空 = 未登録（保存は null。表示で NV と書かない） | 空欄、または直前の AI 値は再読取で上書き |
| 生産国 | `origin` | `origin` | 任意。実在国の日本語名（候補入力）。空 = 未設定 | 同上。国名の明記、または検証済み産地対応を同じ国名検証へ通す。言語・輸入者住所・種類・格付けだけでは埋めない |
| 生産者 | `producer` | `producer` | 任意 ≦100 | 空欄、または直前の AI 値は再読取で上書き |

種類（12 種。ワインは色・泡・瓶から赤／白／ロゼ／スパークリング／オレンジを優先し、不明なときだけ `wine`）も 3 画面とも AI が入れる。触った欄とボトル選択中の種類は上書きしない。ボトル等で埋まった AI 印なしの値も上書きしない。確度 0.5 未満は捨てる。

### 2.1 画面ごとの＋α（共通識別ではない）

| 画面 | ＋α | 入れ方 |
|---|---|---|
| 飲酒記録 | 量・度数・日時・場所・メモ | 量・度数は従来どおり AI。場所は現在地＋店名（手入力）。1 タップ記録は識別・場所を付けない |
| セラー | 本数・保管日・保管場所・購入情報・メモ | 保管場所の新規省略は「自宅セラー」。保管日の新規省略は撮影日（無ければ JST 当日） |
| ノート | 評価・外観 / 香り / 味わい / 余韻 | 手入力。評価は必須・未選択のまま |

### 2.2 サーバーのスナップショット

記録の `drinkName` 優先（キー未指定時）: **ボトル名 > マイドリンク名 > ボディの `drinkName`**。

ボトル選択時（作成・更新とも）:

- `drinkName` / `drinkType` は **ボディにキーがあればその値をスナップショット**。省略時だけボトルの現在値へ fallback。空文字 / `null` は「消す」であり、ボトル値を再投入しない
- `producer` / `origin` / `variety` / `vintage` も同じ（ボディにあれば採用、省略時はボトルからコピー）
- ボトル ID だけを送る従来クライアントは、未指定キーをボトル現在値で埋められる

ノートの `drinkName` / `drinkType` も同じ。識別 3 項目と `vintage` はボディがあれば採用、省略時はボトルからコピー（作成時）。

`origin` の新規 / 変更は実在国の日本語名へ正規化してから保存する。既存の不正値は、その欄を変えない更新では保持する（無関係な編集を壊さない）。一括変換はしない。

1 タップ（`POST /api/my-drinks/:id/log`）は識別列・場所列を **null** のまま作る。

## 3. 撮影日を登録日の既定にする

写真を付けたとき、日付欄をユーザーが触っていなければ撮影時刻を入れる。

| 画面 | 対象欄 | 未来のとき |
|---|---|---|
| 記録 | `drunkAt` | サーバー現在 +15 分を超えたら **いま** にクランプ（既存の未来ルール） |
| ノート | `tastedOn` | JST 今日 |
| セラー | `storedOn`（新規。未操作のとき） | JST 今日 |

取り出し順:

1. JPEG の EXIF `DateTimeOriginal` → `DateTimeDigitized` → `DateTime`
2. 失敗時は `File.lastModified`
3. EXIF の `YYYY:MM:DD HH:MM:SS` は **Asia/Tokyo** として `tokyoLocalToIso` する（端末 TZ に依存しない）

再編集（処理済み JPEG）では EXIF が消えるので、最初に取った `capturedAt` を維持する。AI には送らない。依存パッケージは増やさない（自前パーサ）。

`?date=` で過去日を開いた記録は、ユーザーが日時を触っていなくても **クエリの既定を維持**する（撮影日で上書きしない）。

## 4. 飲酒記録の場所

| 列 | 型 | 規則 |
|---|---|---|
| `place_name` | text nullable ≦100 | 店名など。trim 後空は null |
| `place_lat` / `place_lng` | real nullable | **両方揃える**。片方だけは 400。範囲 lat −90〜90、lng −180〜180 |

- 新規記録フォームだけ、設定「現在地を記録する」（S12。`localStorage` `logs.recordLocation`。既定 ON）が ON のとき、マウント時に `navigator.geolocation.getCurrentPosition` を **1 回**試す。OFF・拒否・失敗でも保存できる
- 設定で ON にした瞬間にも 1 回取得を試し、端末の許可ダイアログを出せる。ブラウザ許可の取り消しはアプリからはできない
- SPA の `Permissions-Policy` は `geolocation=(self)`（`public/_headers`）。空の許可リストだと取得できない
- 編集では自動取得しない。店名の手入力と、既存座標の維持は可
- URL は保存しない。表示時にだけ生成する
- 生成形: `https://www.google.com/maps/search/?api=1&query=`。座標があれば `lat,lng`、店名だけなら店名
- `<a href>` は自前生成かつ `https:` で host が `www.google.com` / `maps.google.com` のときだけ（ユーザー入力 URL は使わない）
- フォームのリンク文言は「Google マップで開く」にしない。座標ありは「現在地を記録しました」＋「この場所を地図で見る」。店名だけは「この場所を地図で探す」
- 日別行は場所名を **テキストだけ**出す（行全体が Link なのでネスト禁止）。地図へは合計の下「その日いた場所」（1 件なら見出しがリンク、2 件以上は各場所名）
- 緯度経度はサーバーログに出さない。画面にも生の数値を出さない。AI に送らない

## 5. 連続導線の写真引き継ぎ

連続して次の登録へ進むときは、直前の写真を **未紐付けの複製** として次のフォームへ入れる。所有は 1 枚 1 先のまま（同じ `photoId` は付け替えない）。複製は `GET /api/photos/:id/content` → `POST /api/photos`（未紐付け）。失敗してもフォームは写真なしで進める。引き継いだ写真では認識 API を走らせない（識別はすでに埋まっている）。

| 経路 | 入口 | 写真の元 | 次のフォーム |
|---|---|---|---|
| 記録 → ノート | `log-new` 保存後「つける」→ `note-new?fromLog=` | その記録の 1 枚 | ノートの先頭（未紐付け。破棄で DELETE） |
| 開栓 / ボトル詳細 → 記録 | `log-new?bottleId=&from=opened\|detail` | そのボトルの 1 枚 | 記録の写真欄 |
| 開栓 / ボトル詳細 → ノート | `note-new?bottleId=&from=opened\|detail` | そのボトルの 1 枚 | ノートの先頭 |

フォーム内でボトルを選んだときも、写真がまだ無くユーザー撮影でもないときはボトル写真を未紐付け複製する。すでにユーザーが付けた写真（認識用 JPEG がある、または既存の紐付き写真）は上書きしない。ボトル切替で前ボトル由来の未編集写真は残さない。コピー失敗時は再試行でき、写真なしで続けることもできる（黙って写真なし保存へ進まない）。1 タップ記録・練習は対象外。

`log-new` の保存成功後（1 タップ記録・編集保存・練習フォームは対象外）:

1. ダイアログ「テイスティングノートをつける？」
2. 「つける」→ `/notes/new?fromLog=<uuid>` へ `replace`。識別に加え、記録の写真があれば上記の複製で引き継ぐ
3. 「あとで」/ 閉じる → 従来どおり対象日の `log-day?highlight=` ＋ undo トースト

`fromLog` は UUID。`GET /api/drink-logs/:id` で自分の記録だけ読む。他人・不在は `not-found`。

引き継ぎ: `drinkName`, `drinkType`, `vintage`, `variety`, `producer`, `origin`, `bottleId`, `tastedOn = drunkOn`、写真（複製）。評価は未選択のまま（必須）。

ノート作成時に飲酒記録は作らない（逆方向のみ。要件 1.5 の v1.x とは別）。

## 6. AI 読取

3 エンドポイントは維持。日次 30 回 / JST 日の `ai_usage` は共有。出力上限はプロファイルに従う（Gemini 抽出 4096 / 検索 2048。Llama は 500 / 400）。記録・ノートを 500 に揃えない。

| API | 返す欄 |
|---|---|
| `POST /api/drink-logs/recognize` | 品名 + 識別 4 項目 + 種類 + 量 + 度数 |
| `POST /api/tasting-notes/recognize` | 品名 + 種類 + 識別 4 項目（ヴィンテージ含む） |
| `POST /api/bottles/recognize` | 既存（品名・識別・種類・度数）。`origin` は生産国寄り。度数はクライアントが捨てる |

モデル出力の `name` / `drinkName` はどちらも品名として受け取る。プロンプトにユーザー文を入れない。

写真の上げ直し・撮り直しで再読取したときは、**空欄と直前に AI が入った欄を新しい候補で上書き**する。ユーザーが触った欄は残す。

生産国・品種の自動入力規則は [ai-recognition.md](ai-recognition.md) を正とする。ラベル明記と検証済み産地対応、確認済み出典以外は空欄にする。confidence だけでは決めない。3機能の既定モデルは同じ Gemini 3.7 Flash。セラー・ノートは単段のまま（商品照合なし）。

## 7. 記録フォームの順

写真 → 品名 → 種類 → ボトル → ヴィンテージ / 品種 / 生産者 / 生産国 → 量 → 度数 → 日時 → 場所 → メモ → 保存。

品名・識別・場所は任意。初期赤ワイン 125 / 12 の 1 タップ保存は維持。メモのプレースホルダは「味や相手など」（場所欄と重複させない）。

## 8. セキュリティ

| 観点 | 規則 |
|---|---|
| 認可 | `fromLog` もセッションの `user.id`。他人は 404 |
| 場所 URL | 自前生成のみ。`javascript:` や任意ホストを描かない |
| XSS | 品名・店名・識別はテキスト |
| 位置 | ログに座標を出さない。AI に送らない |
| 入力 | 識別 ≦100、ヴィンテージ範囲、緯度経度の対 |

## 9. 決定事項

| 項目 | 決定 |
|---|---|
| 1 タップ記録 | 識別・場所は付けない。ノート導線も出さない |
| 記録の写真なし | 識別は手入力可。日時は従来の「いま」/ `?date=` |
| ノートの写真コピー | 連続導線では未紐付け複製。同じ id は共有しない |
| 場所の保存 | 店名＋任意の座標。URL は持たない |
| 現在地の取得 | 設定「現在地を記録する」（S12。既定 ON）。日別は「その日いた場所」から地図へ |
| セラーのラベル | 品名 / 生産国 / ヴィンテージに揃える |
