# 味わい中（開栓したボトルを数日かけて記録する）

- 状態: **提案（オーナー承認待ち）**。承認後に同じ PR で実装し、下の「同期するドキュメント」を更新する
- 背景: いまは「開栓する」でボトルが即 `consumed`（貯蔵庫）になる。ワインやウイスキーは数日〜数か月かけて飲むため、2 日目以降の記録先が見つけにくい。貯蔵庫が「終わったボトルの置き場」に見え、飲み切ったことも残せない
- 見直す過去の決定: 2026-09-06「棚に残す開栓済み（`opened`）は持たない」。本仕様で **`opened` を「味わい中」として復活**させる。棚の陳列には混ぜず、上部の補助表示にだけ出す
- 対象外（今回やらない）: 容量・残量の目安、飲み切りの自動判定、通知、飲み切りの友達共有

---

## 1. 状態と用語

| DB 値 | 画面の名前 | 置き場 | 主な操作 |
|---|---|---|---|
| `sealed` | 未開栓 | 棚（陳列） | 開栓する |
| `opened`（新設） | **味わい中** | セラー上部の「味わい中」列（丸アイコン）と、ホームの「味わい中」 | 飲んだ量を記録 / 飲み切った / 開栓を取り消す |
| `consumed` | 貯蔵庫（飲み切ったボトル） | 貯蔵庫 | 飲んだ量を記録（付け忘れ用） / 味わい中に戻す |

```
 追加            開栓する              飲み切った
 ───►  未開栓  ─────────►  味わい中  ─────────►  貯蔵庫
          ▲                  │   ▲                 │
          └─ 開栓を取り消す ──┘   └── 味わい中に戻す ─┘
```

| 用語 | 意味 |
|---|---|
| 開栓日 | `opened_on`（JST 日）。「開栓する」でセット |
| 飲み切り日 | `consumed_on`（JST 日）。「飲み切った」でセット。**既存の `consumed_on` は意味が「開栓日」から「飲み切り日」に変わる**（移行は 6 章） |
| 手元のボトル | 未開栓 + 味わい中。ヘッダー「セラー N 本」はこれを数える |

### 文言の決まり

「味わい中」は「今も飲んでいる」とも読めるため、**状態の名前（見出し・ピル・状態テキスト）にだけ使う**。

- 「味わい中のボトルがあります」「続きを飲みましょう」などの声かけ・促す文・通知は出さない（[character.md](../character.md) の飲酒助長の禁止）
- 味わい中の列・ホームの節にキャラクターを置かない
- 飲み切りの操作名は「飲み切った」

## 2. セラー（`bottle-list`）

### 2.1 味わい中の列（新設。C15）

棚の陳列とは**別の補助表示**として、ヘッダーと「表示・絞り込み」の間に 1 行だけ置く。棚板・棚の段には混ぜない。

```
┌──────────────────────────────────┐
│ 貯蔵庫      セラー  12 本  まとめて追加│  12 本 = 未開栓 10 + 味わい中 2
├──────────────────────────────────┤
│ 味わい中  (●) (●)                  │  丸アイコン 44px を横並び。はみ出したら横スクロール
│              表示・絞り込み ▾      │
│ 赤ワイン 6本          すべて見る › │  ← 棚は未開栓だけ（これまでどおり）
│  🍾 🍾 🍾 🍾 →                    │
│ ═══════════════════════════════ │
└──────────────────────────────────┘
```

| # | 要素 | 内容・挙動 | データ / API |
|---|---|---|---|
| C15 | 味わい中の列 | 見出し「味わい中」（13px muted）の右に丸アイコンを横並び。**1 本も無ければ列ごと出さない**。棚表示・管理一覧のどちらでも出す。並びは開栓日の新しい順 | `GET /api/bottles?view=opened` |
| C15a | 丸アイコン | 直径 44px（`--tap-min`）の円。表面の写真を `object-fit: cover`・`object-position: center 55%`（ラベル付近）で切る。写真なしは種類のシルエットを円の中に。**文字は重ねない**。アクセシブル名は品名。タップで `/cellar/:bottleId` | `thumbPhotoId`, `thumbPhotoKind`, `drinkType`, `name` |
| C15b | 横スクロール | 7 本を超えたら横スクロール（`scroll-snap`）。行の高さは固定し、棚の位置を押し下げない | — |
| C15c | 絞り込み | 「表示・絞り込み」の検索・種類で絞っているときは、同じ条件で列も絞る。該当 0 本なら列を出さない | `q`, `drinkType` |

- 棚（種類ごと）・種類グリッド・管理一覧は **未開栓（`sealed`）だけ**を出す（これまでどおり）。種類の見出し「赤ワイン 6本」も未開栓だけを数える
- ヘッダー C2「セラー N 本」は **未開栓 + 味わい中**（手元のボトル）を数える

### 2.2 状態

| 状態 | 表示 |
|---|---|
| 味わい中 0 本 | C15 を出さない（余白も取らない） |
| 読み込み中 | C15 は出さない（棚のスケルトンだけ）。届いたら出す |
| 取得失敗 | C15 を出さない（棚の表示を優先。棚側のエラー表示に任せる） |
| 在庫 0（未開栓 0・味わい中あり） | C15 を出したうえで、棚は空状態（キャラ・「ボトルを追加」） |

## 3. ボトル詳細（`bottle-detail`）

### 3.1 未開栓のとき

これまでどおり主ボタン「開栓する」。成功したら詳細に留まり、状態が「味わい中」に変わる。開栓後シート T3b（「飲んだ量を記録」「今はしない」）もこれまでどおり出す。

### 3.2 味わい中のとき

```
│ シャトー○○                        │
│ 赤ワイン ・ 2020                   │
│ 味わい中（9月22日に開栓）           │  状態テキスト。色だけで示さない
│         🍷（写真はそのまま）        │
│ 開栓を取り消す                     │  記録が 1 件も無いときだけ（テキストリンク）
│ ボトル情報 / 購入・保管 / メモ …    │
│ 記録                              │  このボトルの記録（最新 3 件。これまでどおり）
├──────────────────────────────────┤
│ [ 飲んだ量を記録 ] [ 飲み切った ] │  下部に横並び。左が主、右が副
```

| # | 要素 | 内容・挙動 | データ / API |
|---|---|---|---|
| T0c | 状態 | 「味わい中（2026年9月22日に開栓）」 | `status`, `openedOn` |
| T3c | 飲んだ量を記録 | Button 主。`/logs/new?bottleId=&from=detail` | — |
| T9 | 飲み切った | Button 副。**確認なし**で即時 `POST /api/bottles/:id/finish`。送信中は「更新中…」。成功で詳細に留まり、状態が「飲み切り」に変わる。トースト「飲み切りにしました」+「取り消す」（6 秒。`reopen`） | `POST /api/bottles/:id/finish` |
| T10 | 開栓を取り消す | テキストリンク。**このボトルの記録が 1 件も無いとき**だけ出す（押し間違いの救済）。即時 `POST /api/bottles/:id/restore` → 未開栓に戻り、棚の種類の先頭へ | `POST /api/bottles/:id/restore` |

## 4. 記録（`log-new` / `log-edit`）

| # | 要素 | 内容・挙動 | データ / API |
|---|---|---|---|
| N8 | ボトル選択 | ピッカーの並びを **味わい中 → 未開栓 → 貯蔵庫** のグループ順にする。各グループの見出しを出す（「味わい中」「セラー」「貯蔵庫」） | `GET /api/bottles?view=all&scope=accessible`（`status` で分ける） |
| N8c | 飲み切った（新設） | 選んだボトルが**味わい中**のときだけ、ボトル行の下にスイッチ「このボトルを飲み切った」（既定 OFF）。ON で保存すると、記録の保存に成功したあと `finish` を呼ぶ。`finish` だけ失敗したら記録は残し、トースト「記録は保存しました。飲み切りにできませんでした」 | `POST /api/drink-logs` → `POST /api/bottles/:id/finish` |
| N8d | 未開栓を選んだとき（新設） | 選んだボトルが**未開栓**のとき、ボトル行の下に補足「保存すると開栓して味わい中になります」。記録の保存に成功したあと `open` を呼ぶ | `POST /api/drink-logs` → `POST /api/bottles/:id/open` |

- `log-edit` では N8c / N8d を出さない（編集で状態は変えない）
- 貯蔵庫のボトルを選んでも状態は変えない

## 6. データ（`bottles`）

| 列 | 変更 |
|---|---|
| `status` | CHECK を `sealed` / `opened` / `consumed` の 3 値にする（SQLite はテーブル作り直し） |
| `opened_at` | 新設。integer（UTC ms）。`opened` / `consumed` のとき必須、`sealed` は NULL |
| `opened_on` | 新設。text `YYYY-MM-DD`（JST）。`opened_at` からサーバー算出 |
| `consumed_at` / `consumed_on` | 意味を「飲み切り日時 / 日」に変える。`consumed` のときだけ必須 |
| `sort_order` | これまでどおり未開栓の種類内だけ意味を持つ。未開栓に戻ったら種類の先頭 |

移行（マイグレーション 1 本）:

1. 既存の `consumed` 行は **飲み切り扱いのまま**貯蔵庫に残す
2. その行の `opened_at` / `opened_on` に、今の `consumed_at` / `consumed_on`（これまでの開栓日）を写す
3. 飲み切り日と開栓日が同じ日になるので、貯蔵庫のバッジ・詳細は同じ日なら「開栓・飲み切り 9/5」と 1 つにまとめて出す
4. 本当は飲みかけのボトルは、利用者が「味わい中に戻す」で戻す

索引は既存の `(cellar_id, status)` を使う。味わい中の並び用に `(cellar_id, opened_at)` を足す。

## 7. API

| メソッド・パス | 遷移 | 備考 |
|---|---|---|
| `POST /api/bottles/:id/open` | `sealed → opened` | 開栓。`opened_at` / `opened_on` をセット。友達への共有用 `openingEventId` を返す（今の `consume` と同じ） |
| `POST /api/bottles/:id/finish` | `opened → consumed` | 飲み切り。`consumed_at` / `consumed_on` をセット |
| `POST /api/bottles/:id/reopen` | `consumed → opened` | 味わい中に戻す。`consumed_at` / `consumed_on` を NULL |
| `POST /api/bottles/:id/restore` | `opened → sealed` | 開栓を取り消す。`opened_*` を NULL、種類の先頭へ。**互換のため当面 `consumed → sealed` も受ける**（古い端末の「開栓の記録を取り消す」） |
| `POST /api/bottles/:id/consume` | `sealed → opened` | **互換のため当面残す**（古い端末の「開栓する」）。`open` と同じ動き。次の段階で廃止 |

- 4 つとも空オブジェクト可、任意で `expectedVersion` / `operationKey`（共有ボトルは `expectedVersion` 必須）。今の `consume` / `restore` と同じ
- 状態が合わないときは今と同じ規則（開栓済みの `open` は 409 `conflict`、それ以外の不一致・非メンバー・不明は 404）
- 記録（drink-log）は作らない・消さない

一覧（`GET /api/bottles`）:

| `view` | 返すもの | 並び |
|---|---|---|
| `cellar` | 未開栓だけ（変更なし）。応答に `openedCount`（同じセラー・同じ絞り込みの味わい中の本数）を足し、ヘッダーの本数に使う | 変更なし |
| `opened`（新設） | 味わい中だけ。`q` / `drinkType` / `cellarId` / `scope=accessible` を受ける | `opened_at` 降順、同値は `id` 降順 |
| `archive` | 飲み切りだけ | `consumed_at`（飲み切り日時）降順 |
| `all` | 3 状態すべて（記録のボトル選択） | 変更なし（グループ分けはクライアント） |

応答の `Bottle` / 一覧の行に `openedAt` / `openedOn` を足す。

共有セラーの履歴（`cellar_activity`）に `bottle_opened`（開栓）・`bottle_finished`（飲み切り）・`bottle_reopened`（味わい中に戻す）を足す。既存の `bottle_consumed` は過去の行の表示用に「開栓」のまま残す。

認可: すべて今の `consume` / `restore` と同じくセラーのメンバーだけ。他人・不明のボトルは 404。

## 8. 共有セラー・友達

- 状態（味わい中・飲み切り）は参加者全員に共有される。誰が操作しても同じボトルの状態が変わる
- 友達への「開栓」の共有はこれまでどおり開栓のとき（`open`）に出す。飲み切りの共有は今回は作らない
