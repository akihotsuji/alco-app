# 初回ガイド

2026-09-08 オーナー指示。目的は全機能の説明ではなく、次の理解を短時間で得てもらうこと。

- 飲んだ量を残すのが「記録」
- 持っているボトルを管理するのが「セラー」
- 味や感想を残すのが「ノート」
- 写真やボトル関連付けは、必要なときだけ使える
- まず一つの操作ができれば、そのまま使い始められる

見れば分かるボタンを順番に読み上げるツアーは作らない。タイマーだけで進めない。説明を読ませるために操作を待たせない。

画面の正本は [screen-designs/08-first-run-guide.md](../screen-designs/08-first-run-guide.md)。

## 1. 設計表

| 時点 | ユーザーがその時点で疑問に思うこと | 説明する一文 | 案内対象の実操作 | 次へ進む条件 | スキップ・終了時の挙動 |
|---|---|---|---|---|---|
| 初回ホーム（データなし） | 何から始めればよいか。全部使わないと始まらないのか | 使い方を少し試してみますか？ | 「操作を試す」「今はしない」 | 「操作を試す」でホームの記録ボタンへ | 「今はしない」またはシートを閉じる。`skipped` をユーザー単位で記憶。実データは変えない。以後は自動表示しない |
| ホームの記録ボタン | 飲んだ量はどこに残すのか | 飲んだ量は、ここから残せます | ホーム H8「お酒を記録する」を実際にタップ | ユーザーが H8 をタップしたときだけ練習フォームへ | 「ガイドを終了」で `skipped`。H8 以外（写真から記録・中央タブ・カメラ）はガイド中は本番の撮影・保存へ進まない |
| 練習フォーム | 写真が必要か。今の操作で本当に保存されるか | 量を選んで保存。写真はなくても大丈夫です | 量を変えて「練習として保存（記録されません）」 | 練習保存をタップ | 戻る・再読込・途中終了でも保存 API / 写真 / 認識 / 集計 / 開栓は呼ばない。本番の下書きは消さない |
| 練習のあと | 他にも必須の操作があるのか | 基本の操作はこれだけです | 「ガイドを終了」 | 終了をタップ | `completed` を記憶。練習値は本番フォーム・マイドリンクへ持ち込まない。キャラは短く 1 回ウィンク |
| セラー初回（空） | セラーは何をする場所か | 持っているボトルを、ここに並べて管理します | 既存の空状態の「ボトルを追加」 | 画面を見た時点で案内済み。追加は任意 | 既存空文言と重複するツアーは出さない。1 回だけ。スキップ専用ボタンは足さない |
| ノート初回（空） | ノートは記録と何が違うか | 味や感想は、ノートに残します | 既存の空状態の「ノートを作成」 | 画面を見た時点で案内済み。作成は任意 | 同上。記録の練習をここへ続けない |

セリフは一度に 1〜2 文。文字は一括表示（タイプ演出なし）。マスコットは案内時に対象を見る、操作後にこちらを見る、終了時に短くウィンクする。

## 2. 記憶と対象

| 項目 | 決定 |
|---|---|
| 保存先 | `localStorage` `guide.first-run`。キーに `userId` を含め、端末内でユーザー単位 |
| 状態 | `unset` / `skipped` / `completed` / `existing` |
| 自動表示 | `unset` かつ、飲酒記録・マイドリンク・ボトル・ノートがすべて 0 のときだけ招待を出す |
| 既存ユーザー | いずれかの実データがある場合は `existing` を静かに書いて自動開始しない |
| 再実行 | 設定「操作 › 使い方を見る」。データ有無に関係なく最初からやり直せる |
| セラー / ノート初回 | 同じ JSON の `cellarHintSeen` / `notesHintSeen`。空状態を見たときに立てる |

サーバー API・設定画面の健康項目は増やさない。

---

## 3. 練習の禁止事項

練習中は次を実行しない。

- `POST /api/drink-logs` ほか保存 API
- 写真取得・権限要求・`photo-edit`
- 認識 API
- 集計の更新
- 開栓 / 復元
- マイドリンクへの書き込み

常に「練習中・保存されません」を出す。本番の「記録を保存」を見せて無効化するだけにしない。練習専用の保存操作にする。
