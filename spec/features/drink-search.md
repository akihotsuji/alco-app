# お酒の Google 検索導線

セラー・飲酒記録・テイスティングノートの品名付近から、Google 検索を別タブ（または OS の外部ブラウザ）で開く。写真の AI 認識で入った値も、手入力も、既存データも同じ規則で調べられる。

- 状態: **実装**
- 画面: [03-log.md](../screen-designs/03-log.md)、[04-cellar.md](../screen-designs/04-cellar.md)、[05-notes.md](../screen-designs/05-notes.md)、[00-common.md](../screen-designs/00-common.md) 2.11
- 識別項目: [register-identity.md](register-identity.md)
- 色: [design-system.md](../design-system.md) `--search-link`
- 実装: `src/shared/drink-search.ts`、`src/client/components/form/DrinkSearchLink.tsx`

---

## 1. 目的

画面上のお酒の品名などを使い、ユーザー自身が商品情報を調べる。アプリは検索語と URL を端末内で組み立て、クリック時だけ Google を開く。

### 対象外

- Google API 契約、検索プロキシ、スクレイピング、AI への再送信
- 検索結果の取得・順位の固定
- 品名そのものやカード全体を検索リンクにすること
- セラー棚・飲酒記録一覧・ノート一覧の各項目、まとめて登録の各行、マイドリンク独立画面への追加
- 新しい飲酒記録の詳細ページ
- Service Worker / PWA scope を Google に広げること
- 写真の有無や AI 認識の成功を表示条件にすること

---

## 2. 対象画面と配置

表示は全画面で「青い虫眼鏡＋Googleで調べる」。品名の左にアイコンだけは置かない。入力エラーがあるときはエラーを入力欄の近くに保ち、その後に検索リンクを置く。AI 印・必須表示・ラベル関連付けは壊さない。

| 画面 | 位置 | 参照値 |
|---|---|---|
| セラー新規・編集 | 品名入力の直下 | 現在のフォーム state |
| セラー詳細（開栓済み含む） | 品名見出しの直下 | 表示中のボトル |
| 飲酒記録 新規・編集 | 品名入力の直下 | 現在のフォーム state |
| ノート新規 | 品名入力の直下 | 現在のフォーム state |
| ノート編集 | 商品情報が閉じていても要約の品名付近。開いたときは入力欄側だけ（二重表示しない） | 現在のフォーム state |
| ノート詳細 | 本文の品名の直下（写真の次） | 表示中のノート |

商品情報が変えられる画面では、保存前でも検索できる。フォームの保存可否と検索可否は切り離す。編集中は最新 state から URL を作る（保存済み値や元の AI 応答を固定しない）。紐づいたボトルの最新情報ではなく、その画面が表示しているレコード／フォームの情報を使う。

## 3. 検索語

副作用のない共通関数 `buildDrinkSearchQuery`。順序は **生産者 → 品名 → ヴィンテージ（必要なとき） → 酒類（必要なとき）**。有効な要素だけを半角スペースで連結する。

| 項目 | 規則 |
|---|---|
| 品名 | 必須。画面表示に対応する生のフィールド値 |
| 生産者 | 有効で、品名に含まれていなければ先頭へ |
| ヴィンテージ | `isWineFamily` の酒類に限り、trim 後に 4 桁全体が `vintageSchema`（1800〜2100）に一致するとき。品名に独立した同年号があれば付けない |
| 酒類 | 生産者がなく、品名が一般名称リストと完全一致し、既存の酒類が分かるときだけ末尾へ。wine 系は「ワイン」。`other` / 未設定は付けない。同じ語を既に含むときは重ねない |
| 国・産地・品種 | 独立属性としては付けない。品名に含まれる語は削らない |
| 使わない | 感想、評価、価格、購入店、場所、日付、セラー名、ユーザー情報、写真 URL、内部 ID、「口コミ」「通販」等の固定語、引用符、`site:`、言語・地域・期間制限 |

### 3.1 空値・仮表示

- null / undefined / 空 / 空白だけは欠損
- 検索用コピーだけ、前後空白を除き改行・タブ・連続空白を単一スペースにする。保存値は変えない
- UI 代替表示（「（品名未入力）」「解析中…」等）を商品名として渡さない
- 正規化後の完全一致で除外: 不明 / 未入力 / unknown / n/a / （品名未入力） / 解析中 / 解析中… / 解析中...（英字は大小無視）
- 部分一致では除外しない（例: Unknown Pleasures）
- 品名が欠損・仮値ならリンク非表示。生産者や年号だけでは出さない
- 品名が有効なら、任意項目の欠損・入力エラーで検索全体を止めない

### 3.2 重複

比較用は NFKC・英字小文字・空白正規化。検索に出す表示文字列はむやみに書き換えない。

- 英字の生産者は単語境界。短い語が別単語の一部にあるだけでは重複にしない
- 日本語等は連続する生産者表記が品名に含まれるとき重複
- 会社名接尾辞の削除や翻訳名・略称の推定はしない
- 年号は数字境界。「2022年」は同年号、「120220」の一部は年号にしない

### 3.3 年号

- `parseInt` で「2022abc」を採用しない。入力途中の「20」、NV、NaN、範囲外は除外
- ワイン判定は既存 `isWineFamily`（赤／白／ロゼ／スパークリング／オレンジ／ワイン）。ラベル文字列から推測しない
- 日本酒の製造年、ウイスキーの熟成、飲酒日・購入日をヴィンテージの代わりに加えない
- 酒類未設定なら独立した年号フィールドは省略する。品名に含まれる年号は維持する

### 3.4 一般名称

曖昧さ判定に AI / 外部 API は使わない。完全一致リスト:

シャルドネ / Chardonnay、ピノ・ノワール / ピノノワール / Pinot Noir、カベルネ・ソーヴィニヨン / カベルネソーヴィニヨン / Cabernet Sauvignon、メルロー / Merlot、ソーヴィニヨン・ブラン / ソーヴィニヨンブラン / Sauvignon Blanc、純米 / 純米酒 / 純米吟醸 / 純米大吟醸 / 吟醸 / 大吟醸 / 本醸造。

例: シャルドネ ワイン、純米吟醸 日本酒。推測の商品情報は生成しない。

## 4. 外部リンク

- 固定 HTTPS `https://www.google.com/search`。`URL` / `URLSearchParams` で `q` をセット。手動連結や二重エンコードはしない
- 標準の `a`。`href`、`target="_blank"`、`rel="noopener noreferrer"`。React Router の内部遷移にしない
- 描画時・入力時に外部通信しない。クリックしたときだけブラウザが Google を開く
- `window.open` は使わない。フォーム送信・自動保存・画面遷移・写真削除・認識の再実行を起こさない
- 別タブ検索のために未保存破棄ダイアログは出さない。アプリ内の離脱ガードは維持する
- コンポーネントには name / producer / vintage / drinkType だけを渡す。商品オブジェクト全体を URL へ載せない
- セラーの `name` と記録・ノートの `drinkName` は呼び出し側で name にマッピングする
- href は自前生成かつ `https:` / host `www.google.com` / pathname `/search` のときだけ描く

## 5. 見た目・アクセシビリティ

- 文言は「Googleで調べる」
- lucide `Search`（装飾 `aria-hidden`）の右にテキスト
- 色は `--search-link`（ライト `#315F85`、ダーク `#93BCE0`）。primary / accent は一括変更しない
- 塗りボタンにせず、下線のあるテキストリンク。本文コントラスト 4.5:1 以上
- 文字 14px 以上（`--text-note`）、タップ領域 44px 以上
- 支援技術名: `Googleで『{品名}』を検索（新しいタブまたは外部ブラウザで開きます）`
- 長い品名・320px 幅では折り返す。品名と同じ行へ無理に押し込まない
- キーボード操作と `:focus-visible` のリングを維持する

---

## 6. PWA と入力保持

デスクトップの通常ブラウザでは別タブ。スマホ PWA では OS / ブラウザにより外部ブラウザが開くことがある。特定アプリで開くことは保証しない。

検索して戻ったとき、品名・生産者・年号・評価・感想・写真選択をアプリ側の処理で消さない。外部検索のためにフォームをアンマウント／リセットしない。通常の往復での保持を受け入れ条件とする。OS によるプロセス破棄後まで React state が残るとは主張しない。既存の下書き復元は壊さない。永続下書き基盤の新設はしない。
