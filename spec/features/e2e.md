## 1. 目的

壊れやすい横断導線を固定する。全画面網羅・ビジュアルリグレッション・実 iOS クラウドは対象外。

| シナリオ | 導線 | 合格条件 |
|---|---|---|
| A | サインアップ → 記録 → サマリー数字 | 今日のカードと週サマリーに杯数・純アルコールが出る |
| B | サインアップ → ボトル登録 → ノート作成 | ノート詳細が登録したボトルを指す |
| C | OS ダーク × アプリライト | 設定ラベルとノート作成の入力・保存ボタン名が見える |
| D | 設定「動きを減らす」タップ | タブバーが伸びず、使い方を見る／ログアウトが見える |
| E | 酒記録で写真を選ぶ | `photo-edit` を挟まず詳細入力に写真が出る。拡大を閉じて入力が残る。設定に色補正が無い |

写真アップロードはファイルchooser。初期は写真なしでも両シナリオを満たす（ボトルは必須。ロードマップどおり）。

## 2. 実行環境

| 項目 | 決定 |
|---|---|
| ランナー | Playwright。CI は **Chromium のみ**。ローカルで WebKit は任意 |
| 起動 | Vite + Cloudflare プラグイン。`CLOUDFLARE_VITE_FORCE_LOCAL=true` で Workers AI のリモートプロキシを切る（CI に `CLOUDFLARE_API_TOKEN` を置かない）。`wrangler dev` との二重起動はしない |
| 死活 | `GET /api/health` が 200 になるまで待つ |
| D1 | ローカル D1。CI は webServer 前に `pnpm db:migrate:local` |
| 並列 | **1**（ローカル D1 ファイル競合を避ける） |
| リトライ | CI は最大 2。ローカルは 0 |
| タイムゾーン | `Asia/Tokyo`（日付境界ずれを防ぐ。相対「今日」だけ見る） |
| ビューポート | スマートフォン幅（Pixel 相当） |
| ユーザー | 毎回サインアップ。固定シード・本番ユーザーは使わない |
| パスワード | 実行ごとに生成。コード・ログ・spec に本番秘密を書かない |
| `BETTER_AUTH_SECRET` | CI はジョブ内で使い捨て生成して `.dev.vars` に書く。GitHub Secrets / 本番 wrangler secret は参照しない |

`storageState` とトレースは git にコミットしない（`.gitignore` の `playwright/.auth/` / `test-results/` / `playwright-report/`）。

## 3. シナリオ詳細

### 3.1 共通前処理

1. `/signup` で表示名・メール・パスワードを入れて登録する
2. ホームが表示されたら、初回ガイド招待「今はしない」を押す（空ユーザーは [first-run-guide](../screen-designs/) の招待が出る）
3. 位置情報はテストが許可し、東京付近の座標を渡す（記録フォームの geolocation 待ちで止まらないようにする）

### 3.2 シナリオ A（記録 → サマリー）

1. 中央タブ「お酒を記録」→ `/logs/new`（撮影は開始しない）
2. 品名を入れ、種類セレクト（初期は赤ワイン）から「ビール」（350ml / 5%）を選ぶ
3. 「記録を保存」
4. 「テイスティングノートをつける？」は「あとで」
5. 日別に 1 杯と 14.0g が出る
6. ホームの今日カードに「今日は 1 杯記録しています」と 14.0g
7. 「詳しく見る」で週サマリーにも 1 杯と 14.0g

記録保存後のホーム／週サマリーは再読み込みなしで数字が反映される（`useCreateDrinkLog` は `drinkLogs` と `drinkLogSummaries` を無効化する）。

14.0g は `DRINK_TYPE_PRESETS.beer` の計算結果（[alcohol-calculation.md](alcohol-calculation.md)）。種類を変えるときは期待値も同じ PR で直す。

### 3.3 シナリオ B（ボトル → ノート）

1. セラータブ → 空状態の「ボトルを追加」（`/cellar/new`。`?camera=1` は付けない）
2. 品名を入れて「棚に並べる（1 本）」
3. ボトル詳細に品名が出る
4. ノートタブ → 「ノートを作成」
5. 「セラーのボトルと関連付ける」で今のボトルを選ぶ（品名・種類が埋まる）
6. 評価 4 を付けて「ノートを保存」
7. ノート詳細にボトル名が出る

### 3.4 シナリオ C（OS ダーク × アプリライト）

報告された表示崩れの回帰。ビジュアル比較はしない。

1. `prefers-color-scheme: dark` でサインアップする
2. 設定 → 外観「ライト」
3. 「表示名」「メール」「写真にキャラを入れる（既定）」が見え、行の文字色が地色と違う
4. ノート作成で「品種」入力が潰れず、保存ボタン名が見える

### 3.5 シナリオ D（動きを減らすタップ）

報告された「下半分が覆われる」回帰。ビジュアル比較はしない。

1. 設定 → 動きを減らす「常に減らす」
2. `<html data-reduce-motion="1">` が付く
3. radio にフォーカスが残らず、タブバー高さが膨らまない
4. 「使い方を見る」「ログアウト」がタブバーの上に見える
5. 「端末の設定に従う」に戻しても同じ

## 4. CI

`.github/workflows/ci.yml` にジョブ `e2e` を足す。既存の lint / typecheck / test / audit ジョブは変えない。デプロイや `CLOUDFLARE_API_TOKEN` は参照しない。

失敗時だけ Playwright のトレース / レポートを artifact にする。保持は **3 日**（公開リポジトリでも、セッションはジョブ内の使い捨て secret とローカル D1 にしか効かない）。

---

## 4.1 本番ビルド + Service Worker（復旧）

開発サーバー E2E とは別に、`pnpm build` した成果を `wrangler dev --env dev` で配信する（SW が登録される）。`pnpm test:e2e:pwa`。CI の `e2e` ジョブで通常スモークのあとに走らせる。

| シナリオ | 合格条件 |
|---|---|
| 初回と再読み込み | ログイン画面またはホームが出る。空の地色だけで止まらない。SW が active |
| SW 制御下の再読み込み | `controller` がある状態で再訪しても操作できる |
| 認証 GET 遅延 | 「読み込み中」が見える。ログアウト扱いにならない |
| 認証 GET 失敗 | 「読み込めませんでした」と再試行。ログイン画面へ自動遷移しない |
| セッション切れ | 401 / 空セッションは既存どおりログインへ |
| オフライン再起動 | 説明と再試行がある。無条件リロードループにしない |
| 遅延 JS 失敗 | 説明と再試行がある |
| 未保存フォーム + SW 更新通知 | 入力が消えず、更新は離脱保護を通る |
| 長いフォームのスクロール | `.app-content` が伸び、document lock 後も `scrollTop` と入力ができる |

旧ビルド A → 新ビルド B の実デプロイ更新はジョブでは 2 回ビルドしない。SW 更新の分岐は単体テストと、通知イベントの E2E で固定する。

## 5. 対象外

- 切り抜き / ラベル読み取り / Gemini 実 API
- 酒記録の写真選択（中間画面なし・拡大）はシナリオ E。実カメラと実モデル比較は対象外
- 開栓・貯蔵庫・マイドリンク 1 タップ
- WebKit / Firefox を CI で必須にすること
- `pnpm test`（Vitest）への混入。E2E は `pnpm test:e2e` だけ

## 6. セキュリティ

- 本番 URL・本番ユーザー・`BETTER_AUTH_SECRET` の実値をテストやワークフローに書かない
- トレースに Cookie が乗る。public でも保持期間を短くし、`storageState` をコミットしない
- ログにパスワードを出さない
