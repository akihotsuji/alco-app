### 1.2 下部タブ（5）

| 位置 | ID | ラベル | アイコン（lucide） | ルート |
|---|---|---|---|---|
| 1 | home | ホーム | `house` | `/` |
| 2 | cellar | セラー | `wine`（ボトル） | `/cellar` |
| 3（中央） | log | 記録 | `plus`。primary 円 60px | **なし**（作成動作。下記） |
| 4 | notes | ノート | `notebook-pen` | `/notes` |
| 5 | settings | 設定 | `settings` | `/settings` |

- 通常タブ: 高さ 48px、アイコン 20px + ラベル 12px。現在地は inset + primary 色。切替は inset-sm と色が `--dur-state` で移る（M-20。アイコンは動かさない）
- **中央タブ**: 直径 `--tab-center-size`（60px）の円。`--primary` 塗り、アイコン 26px `--primary-fg`、`--shadow-primary`。タブバー上端から 12px 上に出す。ラベル「記録」は円の下 12px。押下は主ボタンと同じ `scale(0.985) translateY(1px)` + pressed inset（M-21）
- **中央タブは「記録」作成ボタンであり着地画面を持たない**（2026-09-08。円内は Plus。下ラベルは「記録」のみ。2026-09-06 (c) 撮影開始は撤回）:
  - タップで `/logs/new` を **写真なし**で開く。カメラ・ファイル選択・権限要求は開始しない
  - 現在地ハイライトは付けない（円は常に outset。inset になるのは押下中の M-21 だけ）。`/logs` 配下の画面はホームタブを現在地にする（[../screens.md](../screens.md) 親タブ）
  - 再タップも `/logs/new` を開く（撮影は始めない。タブ再タップの「根へ戻す」は適用しない）
  - 撮影は `log-new` 内の「写真を撮る」だけ。ライブラリは「写真を選ぶ」。ホームに撮影開始のボタンは置かない
  - `?camera=1` をアプリ内導線に付けない。ディープリンクでも記録・ノートのフォームは自動起動しない
- タブ再タップ（通常タブのみ）: そのタブの根へ戻し、スクロールを先頭へ（`scrollTo({ top: 0, behavior: "smooth" })`。reduced motion では `auto`。M-22）
- タブバー自体・アイコンの跳ね・バッジは動かさない
- 作成・編集画面（`*-new` / `*-edit`）と `photo-edit` では **タブバーを隠す**
- safe-area: 下は `safe-area-inset-bottom`、横向きのノッチは左右 `safe-area-inset-left` / `right`（6-05。トークン `--safe-*`）
- 320px 幅でラベルが折り返す場合は 11px まで縮める（中央ラベルは 12px 固定）

### 1.4 追加 FAB（セラー一覧・ノート一覧）

右利きの親指が届くよう、セラー一覧の追加とノート一覧の作成をタブバーの上・右 20px に置く。ヘッダー右の「＋ 作成」は置かない。中央タブ（記録）とは役割を分け、ホーム・設定・作成/編集・詳細には出さない。

| # | 要素 | 種別 | 内容・挙動 |
|---|---|---|---|
| F1 | 追加 / 作成 | Button 副（円 52px、`plus`） | `bottle-list`: `/cellar/new`（aria「追加」。撮影は自動起動しない）。`note-list`: `/notes/new`（aria「作成」。`bottleId` があれば引き継ぐ。撮影しない） |
| F2 | 位置 | 固定 | 右 20px + `safe-area-inset-right`、下はタブバー上端から 16px + `safe-area-inset-bottom`。`z-index` はタブより上・トーストより下。コンテンツ最下部に FAB 分の余白を足す |
| F3 | 見た目 | 地色 + `--shadow-outset-sm` | ヘッダーの円ボタンと同じ語彙。primary 塗りにしない（中央タブと競合させない） |

空状態の主ボタン（「ボトルを追加」「ノートを作成」）は残す。

### 1.3 スクロールと保存バー

- 作成・編集画面の主ボタンは下部固定バー（高さ 52px + 余白 16px + safe-area）。キーボード表示時も **ビューポート下端に残す**（`position: sticky; bottom: 0` + `100dvh`）
- コンテンツ最下部には保存バー分の余白を足し、最後の入力が隠れないようにする

### 1.5 セーフエリアとビューポート（6-05）

PWA スタンドアロンとノッチ付き端末のための枠。数値の正本は [../qa-devices.md](../qa-devices.md)。

| 場所 | 余白 |
|---|---|
| ヘッダー / `photo-edit` 上バー | 上 `safe-area-inset-top`。左右も加算 |
| ホーム（ヘッダーなし） | コンテンツ上に `safe-area-inset-top`（`.app-shell-no-header`） |
| ログイン / サインアップ | `.auth-page` の四辺 |
| コンテンツ | 左右 20px + left/right。下はタブ分 + bottom |
| タブ / FAB / トースト / 保存バー / ダイアログ | ホームバーと横向きノッチを避ける |
| 高さ | `100dvh`（iOS 17+。`100vh` の二重指定はしない） |
| 入力 | `input` / `textarea` / `select` は 16px 以上（iOS のフォーカスズーム防止） |

折りたたみの特殊ケースと古い OS は対象外。短い横向き（高さ 500px 以下）では `photo-edit` と空状態の余白だけ詰める。タブ高さは変えない。

## 2. 横断部品

### 2.1 トースト

| 項目 | 値 |
|---|---|
| 位置 | 画面下、タブバーの上 16px（タブ非表示時は下 24px）。左右 20px + left/right safe-area |
| 見た目 | 地色 + `--shadow-outset`、角 `--radius`、高さ 52px、左右 20px |
| 内容 | 左: `cheer` 32px（**保存成功時のみ**）、文言 16px、右: アクション（primary 文字、例「取り消す」） |
| 時間 | 5 秒。アクションの操作開始（`pointerdown` / フォーカス）で滞在タイマーを止め、タップ完了まで残す。同時に 1 つ（新しいものが置き換える） |
| 文言 | 「記録しました」「保存しました」「開栓しました」「削除しました」「元に戻しました」「セラーに戻しました」。SW 更新（未保存時）は「新しいバージョンがあります」+ アクション「更新」（キャラなし。押すと既存の離脱保護を通る）。エラーは「保存できませんでした。もう一度試してください」（キャラなし） |
| 出入り | 出現: 下 8px + 不透明 0 → 定位置（`--dur-toast-in` 180ms、M-23）。退場: 不透明度のみ（`--dur-toast-out` 150ms、M-24）。置き換え時は旧を退場させてから新を出す |
| キャラの反応 | `cheer` の水面が 45% → 60% に 1 回上がる（`pour`、`--dur-fill` 400ms、M-25）。目・星は動かさない。エラーには出さない |
| 触感 | 保存成功時に `haptic("success")`（設定 ON の端末のみ。[../motion-design.md](../motion-design.md) 6.5） |

### 2.2 ダイアログ

- 地色カード、角 `--radius-card`、幅 = 画面幅 − 40px、下から 24px 上に浮く（中央でもよいが親指優先で下寄せ）
- タイトル 20px、本文 16px、ボタンは縦積み（主 → 副 → テキスト「キャンセル」）
- 背後は `--foreground` 40% のスクリム。スクリムタップで閉じる（destructive 以外）
- **ソフトキーボード表示中もキーボードの上に出す**（2026-09-07 Issue #60）。viewport meta の `interactive-widget=resizes-content`（Android Chrome）と `visualViewport` から求めた `--keyboard-inset`（iOS Safari）でパネルを持ち上げ、残りの高さに収まらない分は中身（ピッカーなら一覧）をスクロールさせる
- 検索欄を持つピッカー（ボトル）は開いた瞬間に検索欄へ自動フォーカスしない（キーボードで一覧が隠れる）。フォーカスはパネルに置き、検索は任意でタップして始める
- **削除確認**にはキャラクターを出さない。主ボタンは `--danger`
- 開閉: 開くときはパネルが下 12px + 不透明 0 から `--dur-enter` で上がる（M-13）。閉じるときは下 12px へ `--dur-state` で消える（M-30）。スクリムは不透明度のみ

### 2.3 空状態

```
      [Mascot 96px]
   説明 1 行（16px、中央）
   [ 主アクション（Button 主） ]
```

ポーズは画面ごと（[../character.md](../character.md) 4 章）。他ユーザーのサンプルや「みんなの〜」は置かない。

初回描画時に 1 回だけ、キャラが不透明 0 → 1・上 8px → 0 で現れ（M-26、`--dur-enter`）、80ms 遅れて主ボタンが同じ動きで続く（M-27）。以後は静止。同じ空状態を再表示しても再生しない（ref で記録）。

### 2.4 エラー

- 取得失敗: 「読み込めませんでした」＋ Button 副「再試行」。キャラなし
- 保存失敗: フォーム上部に汎用文（トーストではなくインライン。入力は保持）。`navigator.onLine === false` のときだけ文言を **「オフラインです。接続してからもう一度試してください」** にする（X4）。それ以外の失敗理由は区別しない
- 失敗時にボタンを揺らさない・振動させない。主ボタンの水位線（M-04）は `--dur-state` でフェードアウトしてラベルを戻す（M-06）
- 401: ログインへ（`redirect` 付き。`/` から来たときは付けない）。画面側で個別に扱わず `RequireAuth` に任せる（2-04）。404（他人 / 不在）: `not-found`

### 2.10 起動・復旧（ルート共通。新ルートは作らない）

認証待ち・遅延 chunk 待ち・起動スクリプト未完了・ルートの未捕捉エラーで使う。キャラは出さない（2.4）。ニューモーフィズムと地色は既存のまま。引っ張り更新を CSS だけで抑えるための画面ではない。

| 状態 | 文言 | 操作 |
|---|---|---|
| 読み込み中 | 「読み込み中」 | なし |
| 遅い（8 秒） | 「読み込みに時間がかかっています」 | Button 副「再試行」 |
| 失敗（通信・chunk・未捕捉） | 「読み込めませんでした」 | Button 副「再試行」 |

- `#root` の初期 HTML にも同じ「読み込み中」を置く（JS が来る前に空の地色だけにしない）
- 再試行は進行中の認証 GET を取り直し、未ログインにはしない
- オフラインや同じ資産失敗の繰り返しでは無条件 `location.reload()` せず、この失敗 UI を出す

### 2.5 ローディング

- 一覧: 行 / タイルのプレースホルダ 3〜6 個（outset の枠だけ）。**シマー・点滅はしない**（静止）
- 詳細: 写真枠 + 見出し 2 行の枠
- データ到着時はスケルトンと本体を `--dur-state` でクロスフェードする（M-29）
- ボタン押下中: ボタン無効 + ラベル「保存中」。スピナー単独にしない。主ボタンはボタン内の **水位線**（`--fill-tint` の帯）が下端から 1 回だけ上がって満水で止まる（M-04。ループしない）

### 2.5b 押下（全ボタン共通）

- 副ボタン・チップ・タブ: 影 outset → inset を `--dur-press`（90ms）で、戻りは `--dur-release`（160ms、`--ease-settle`）。拡縮なし
- 主ボタン・中央タブ: 上記に加えて `scale(0.985) translateY(1px)`、明度 0.92（M-01 / M-02）
- 押下時の `haptic("light")` は Link の `onClick` / mutation の `onSuccess` で呼ぶ（キャンセルされたタップに振動させない）。既定 OFF
- 詳細は [../motion-design.md](../motion-design.md) 8 章

### 2.6 チップ

- 非選択: `--shadow-outset-sm`。選択: `--shadow-inset-sm` + primary 文字 + 600。切替は `--dur-press`（M-31）
- 1 タップ記録のチップ: 送信中は inset を維持して文字を muted に（M-07）。成功でチップ内に水位線（`--fill-tint-surface`）が 1 回上がって消え、outset へ戻る（M-08）
- 高さ 40px、左右 14px、**間隔 横 12px / 縦 10px**（影のぼかし以上。詰めると隣のハイライトが被る）、横スクロール可（`scroll-snap`）
- 選択解除できるフィルタチップは末尾に `x` を含む
- 2 択の表示切替は「2 択セグメント」（inset-sm の溝 + 選択側だけ outset-sm の玉）。3 択以上はチップ列

### 2.6b 小部品の影

高さ 64px 未満の部品（チップ・タブ・円ボタン・ステッパー・ピル・サムネ・入力欄・週マス）は **`-sm` 系の影**を使う。塗りのある小部品（週マスの記録あり、中央タブ）には inset を重ねない（design-system 影の節）。

### 2.7 写真タイル（撮影前。セラーの追加フォーム）

セラーの追加・まとめて追加は従来の大きな写真タイルを使う。記録・ノートの作成／編集は **2.7b**。

| 項目 | 値 |
|---|---|
| 見た目 | 地色 + `--shadow-inset`、角 `--radius-photo`、高さ 120px、横一杯（セラーは 2:3 100×150 左寄せ） |
| 中身 | 中央にカメラアイコン 28px + 「写真を撮る」16px。右下に `surprised` 48px（セラーでは出さない） |
| タップ | 撮影（`capture="environment"`）→ `photo-edit`（[07-photo-capture.md](07-photo-capture.md)） |
| 副導線 | タイル下にテキスト「ライブラリから」。保存済み写真を選ぶ（`capture` なし） |

### 2.7b 写真の追加操作（記録・ノート）

巨大な写真タイルは使わない。ラベル「写真」の下に小さなボタンを横並びにする。**記録・ノートともフォーム先頭**（種類・銘柄より上）に置く。

| 項目 | 値 |
|---|---|
| 見た目 | 副ボタン 2 つ（outset-sm）。「写真を撮る」「写真を選ぶ」 |
| 撮る | 明示タップでのみ撮影（`capture="environment"`）→ `photo-edit`。独自の「カメラを開きますか？」確認は出さない |
| 選ぶ | 保存済み写真（`capture` なし） |
| 自動起動 | **しない**。画面マウント、再表示、戻る、タブ再タップ、権限許可後の再訪、`?camera=1` でも開始しない |
| キャンセル | 撮影キャンセル・権限拒否ではフォームを閉じず、入力も消さない |

### 2.8 写真（撮影後のサムネ）

- 記録・ノート: 96×120（4:5）、セラー: 100×150（2:3）。角 12px、inset 枠
- 右に「編集」「削除」（テキストボタン）。削除は確認なし（未保存の写真は即破棄）

### 2.9 モーションと reduced motion

- 演出はすべて [../motion-design.md](../motion-design.md) の `M-xx` を参照し、値はモーショントークン（`--dur-*` / `--ease-*` / `--fill-tint*`）だけを使う。その場の数値は書かない
- **動くのは状態変化の瞬間だけ**。待機ループ・シマー・バウンス・発光・ページ遷移のスライドは置かない
- reduced motion: OS の `prefers-reduced-motion: reduce` または設定「動きを減らす = 常に減らす」（06-settings S9）で `AppShell` が `<html data-reduce-motion="1">` を付ける。移動・拡縮・水位線・棚板ハイライト・キャラの動きは無し、不透明度のフェード（≦150ms）と色・影の即時切替だけ残す。`scrollIntoView` / `scrollTo` は `behavior: "auto"`
- 触感フィードバック: `src/client/lib/haptic.ts` の `haptic("light" | "success")` のみ。既定 OFF（06-settings S8）。失敗時は振動しない
