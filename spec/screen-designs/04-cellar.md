2026-09-05（2 回目）のオーナー決定: 棚は **地色の上にガラス風の棚板**、ボトルは **切り抜き**（背景除去を MVP へ）。**種類ごと / 1 本ずつ**の表示切替。**ラベルの AI 読み取り**はセラーのみ（当時は Workers AI。2026-09-10 に記録と同じ Gemini へ揃えた）。

2026-09-06 追記: セラーの操作は **追加**と**開栓**。開栓で貯蔵庫へ移す。棚に残す「開栓済み」と、開栓時の 1 杯記録は持たない。1 杯は記録画面で付ける。

## 概念

```
   追加（撮って登録）                 開栓する
 ─────────────────►  セラー（棚）  ─────────────────►  貯蔵庫（アーカイブ）
                     sealed                              consumed
                          ▲                                 │
                          └────────── 開栓の記録を取り消す（undo） ──┘
```

- **1 行 = 1 本**。登録時の本数 N はサーバーが N 行に展開する（上限 12）
- 棚にある本はすべて `sealed`。開栓済みのまま棚に残す状態は持たない
- **開栓する**は常に 1 本を貯蔵庫（`consumed`）へ移す。確認ダイアログは出さない。**記録は作らない**。1 杯は記録画面（`log-new` のボトル行）で付ける
- 写真は 2:3 に切り、`cellar` プリセットを掛け、**端末内で背景除去**して透過 WebP で保存する（`photos.kind = cutout`）。除去できないときは長方形 JPEG（`kind = photo`）にフォールバックし、棚では角 8px の写真として載せる
- ラベル読み取り: 撮影直後に **切り抜く前の 2:3 JPEG** を `POST /api/bottles/recognize` に送り、返ってきた候補を空欄と直前の AI 印の欄に入れる。ユーザーが確認して保存する（自動保存しない）
- **まとめて追加**（`bottle-batch`）: 何本もあるときは 1 本ずつ撮って行に積み、最後に 1 回で棚に並べる。1 行 = 1 枚の写真 = 1 銘柄（本数 N 可）。API は `bottle-new` と同じ `POST /api/bottles` を行ごとに呼ぶ（サーバー変更なし）

### 開栓のメタファー（[../motion-design.md](../motion-design.md) 9 章。「少し凝った」段階を採用）

- 開栓 = **棚から貯蔵庫へ抜ける**。コルクも液体も描かない。ボトルの写真は動かさない
- 到着した `/cellar` で 3 つが同時に始まり 300ms で静止する（M-10）: ヘッダー「セラー N 本」が N → N−1 にカウント、抜けた本があった段の棚板の上辺 1px の中を明帯（幅 24%、`--shelf-glass-edge`）が左 → 右へ 1 回走る、トースト（M-23 / M-25）。隣の本は再描画で自然に詰まる（FLIP はしない）
- 取り消しで本が戻るときは、そのタイルが上 6px から不透明 0 → 1 で **置かれる**ように現れ（M-11、`--dur-enter`）、段の棚板に明帯（M-32）、本数が N に戻る
- 対象の段は `history.state.left = { bottleId, createdAt }` から `createdAt` 降順の順位で求める（3 列 / 段。480px 以上は 4 列）
- reduced motion では本数の即時差し替えとトーストの不透明度フェードだけ

### 開栓の成功後

1. 開栓 API が完了してから T3b を出す。記録量の推測保存はしない
2. シートを閉じるだけで記録もノートも作らない。キャンセルしても開栓は戻さない（戻すのは T4）
3. フォームへ進んだあとの戻りはボトル詳細。同じ案内は再表示しない

## `bottle-edit` ボトルを編集

`/cellar/:bottleId/edit`。`bottle-new` と同じレイアウト。差分:

- 本数ステッパーは無い（1 行 = 1 本）
- 状態は編集できない（詳細の「開栓する」「開栓の記録を取り消す」で操作）。開栓日は詳細のピル（`consumedOn`）
- 写真の付け替え: **「編集」で切り抜きをやり直す**（保存済みは配信画像から `photo-edit`。カメラは起動しない）。**「撮り直す」「写真を選ぶ」で差し替え**（削除を先に必須にしない。どちらも `photo-edit`）。「削除」はその場で `DELETE`（従来どおり。キャンセルでは戻らない）。裏面（B1b）はサムネ + 削除。無ければ「裏面を撮る」「裏面を選ぶ」。保存時の `PATCH` は `photoIds: [表面, 裏面?]` の全体（外れた写真はサーバーが削除）
- 読み取り: 表面をこのセッションで新しく付けたときだけ自動で走る。裏面だけ追加しても自動は走らない。案内帯「裏面も使ってラベルを読み取れます」+「裏面も含めて読み取る」を出し、保存済み表面を配信から認識用 JPEG にして表 + 裏で読む
- 保存 → `PATCH /api/bottles/:id` → 詳細
- 下部テキストボタン「このボトルを削除」→ 確認ダイアログ「ノートは残ります。記録のボトル名は残ります」（danger）→ `DELETE` → `/cellar`。**貯蔵庫の本も削除できる**
