# 詳細画面設計（screen-designs）

Phase 1-07 の成果物。**全画面の要素・機能・状態・遷移・イメージ図（モック）を画面単位で確定する。** Phase 2 以降の画面実装は、本フォルダの該当ファイルを **そのまま実装する**。

- 状態: **オーナー承認済み**（2026-09-06。本数上限 12・ノート写真 6 も確定。中央タブの挙動は同日 **(c) 中央タブ＝撮影開始** で確定し、「要確認」はすべて解消）
- 前段の骨格: [../screens.md](../screens.md)（ルート・タブ・認証境界）、[../wireframes.md](../wireframes.md)（1-02 の箱図。履歴）
- 見た目の数値: [../design-system.md](../design-system.md)、キャラクター: [../character.md](../character.md)
- モック画像: [../wireframes/mocks/](../wireframes/mocks/)（ソース [preview.html](../wireframes/mocks/preview.html)。ダミーデータ、390×844 @2x）

## 「設計どおりに実装する」ルール

1. 画面を実装・変更するとき、**まず本フォルダの該当ファイルを開き、要素表・状態・遷移・モックの 4 点を満たすように作る**。モックと要素表が食い違うときは要素表が正（モックは質感確認）。
2. 実装中に「こうした方がよい」と思っても、**コードを先に変えない**。同じ PR で該当ファイルとモックを直し、PR 本文に「画面設計の変更点」を書いてオーナーがレビューする。
3. 各ファイル末尾の **受け入れチェック**を、実装 PR のチェックリストにそのまま貼る。全項目にチェックが付かない PR はマージしない。
4. 数値（サイズ・比率・タップ数・文字数）は本フォルダと [../design-system.md](../design-system.md) の値を使う。コードにマジックナンバーを書かない（`ui-design` ルール）。
5. 本フォルダに無い画面は作らない。必要なら先にファイルを追加し、[../screens.md](../screens.md) のルート表も同じ PR で直す。

このルールは [../../.cursor/rules/development-workflow.mdc](../../.cursor/rules/development-workflow.mdc) と [ui-design.mdc](../../.cursor/rules/ui-design.mdc) に転記済み。

## 1-07 で確定した設計判断（レビュー対象）

| 項目 | 判断 | 理由 |
|---|---|---|
| タブ順 | **ホーム / セラー / 記録 / ノート / 設定**。記録が中央 | オーナー指示（記録が最頻）。中央は円形の primary ボタンとして浮かせる |
| 中央タブの挙動 | **記録**作成ボタン（円内 Plus。下ラベルは「記録」のみ）。タップで空の `log-new`。カメラは開かない。着地・現在地ハイライトなし。写真なし記録は中央タブだけ。ホームはサマリー（記録 CTA なし）。日別は一覧・合計・編集・削除 | 2026-09-08。ホームの記録ボタン廃止 |
| 写真の位置づけ | 記録・ノートはフォーム**先頭**の小さな「写真を撮る / 選ぶ」（任意。明示タップのみ）。巨大タイルにはしない。セラー追加は従来の写真タイル | 2026-09-08。撮る操作を先に置く |
| セラーの見せ方 | **棚（陳列）**。地色の上に **ガラス風の棚板**、**切り抜いた**ボトルが 3 本／段で立つ。行リストは廃止 | オーナー指示（2026-09-05 に「ガラス棚 + 切り抜きを MVP」で確定）。除去できないときは長方形写真にフォールバック |
| セラーの表示切替 | **種類ごと**（種類名のゴースト見出し + 横スクロール 1 段）/ **1 本ずつ**（3 列）。既定は 1 本ずつ | オーナー指示（参考画像） |
| ラベル読み取り | ボトル追加時、および編集で新規写真を足したときに写真を **Cloudflare 経由の外部 AI** に送り、品名・生産者・生産国・品種・ヴィンテージ・種類・度数の候補を空欄と直前の AI 値へ入れる。生産国は実在国の日本語名。根拠不足は空欄。自動保存しない。設定で OFF 可。記録・ノート写真も共通識別を推定する。既定モデルは 3 機能で同じ | オーナー決定（2026-09-05 / 2026-09-08 / 2026-09-10）。[register-identity.md](../features/register-identity.md) |
| セラーの操作 | **追加**と**開栓**の 2 つ。開栓 → 貯蔵庫（`/cellar/archive`）へ移る。記録は作らない | 2026-09-06。棚に残す開栓済みと、開栓時の 1 杯記録は不要 |
| 開栓の undo | 棚に戻ったトースト 5 秒「取り消す」= `restore` のみ | 誤タップ救済。確認ダイアログは出さない |
| 1 行 = 1 本 | 登録時の本数 N はサーバーが **N 行に展開**。`quantity` 列は廃止 | 棚に N 本並ぶ。開栓は常に 1 本 |
| ボトルステータス | `sealed`（未開栓 = 棚）/ `consumed`（開栓 = 貯蔵庫）。`opened` は廃止 | 2026-09-06。中間状態を持たない |
| 記録とボトルの紐付け | `drink_logs.bottle_id`（任意）。通常フォームでは保存前の任意行。ボトル詳細・開栓後からは事前関連付け | 何を飲んだかを残す。開栓では自動作成しない |
| ボトル詳細のプロパティ | 品名・種類・ヴィンテージ・品種・生産国・生産者・購入日・価格・購入場所・保管日・保管場所・メモ（空行は出さない） | 2026-09-08。ラベルは [register-identity.md](../features/register-identity.md) |
| ノート一覧 | **横並びカード**（銘柄が主。左に小さめ 4:5 サムネ）。写真なしは種類アイコン | 写真に文字を重ねない |
| キャラクター | ホーム（覗く）、ログイン、空状態、保存トースト、写真合成。会話はしない | [../character.md](../character.md) |
| 影の 2 段階化 | 高さ 64px 未満の部品は `-sm` 影、塗りに inset を重ねない、部品間隔は影のぼかし以上 | 2026-09-05 指摘のデザイン崩れ（週マスの薄赤、チップの被り）を修正 |
| モーション | 状態変化の瞬間だけ動く（押下の 1px 沈み、行の挿入、開栓ピル、トーストの出入り、`cheer` の水面）。各画面の該当行に `M-xx` を記載。reduced motion と haptic（既定 OFF）を共通化 | 2026-09-06 承認の [../motion-design.md](../motion-design.md)。週マスのタップ先をその日の日別に変更（X6）、設定に「操作」節を追加（X5） |
| モック | 質感確認用。要素表と食い違えば要素表が正 | 画像は差分レビューしにくい |

## 各ファイルの書式（テンプレート）

```
## <画面 ID> <画面名>
| ルート | 親タブ | タブバー | ヘッダー | 主アクション（1 つ） |
目的 / モック画像
レイアウト（箱図）
要素表: # | 要素 | 種別 | 内容・挙動 | データ / API
状態: 初期 / ローディング / 空 / エラー / 成功
操作と遷移: 操作 → 結果（タップ数）
バリデーション（入力がある画面）
キャラクター（出す条件・ポーズ・サイズ）
受け入れチェック（実装 PR に貼る）
```

要素表の「種別」は design-system の部品名（Button 主 / Button 副 / Input / Card / Chip / 行 / 写真タイル / 棚 / Dialog / Toast / Mascot）。
