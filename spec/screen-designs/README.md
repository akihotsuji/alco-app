# 詳細画面設計（screen-designs）

Phase 1-07 の成果物。**全画面の要素・機能・状態・遷移・イメージ図（モック）を画面単位で確定する。** Phase 2 以降の画面実装は、本フォルダの該当ファイルを **そのまま実装する**。

- 状態: **オーナー承認待ち**（2026-09-05 指示で作成）

- 見た目の数値: [../design-system.md](../design-system.md)、キャラクター: [../character.md](../character.md)

## 「設計どおりに実装する」ルール

1. 画面を実装・変更するとき、**まず本フォルダの該当ファイルを開き、要素表・状態・遷移・モックの 4 点を満たすように作る**。モックと要素表が食い違うときは要素表が正（モックは質感確認）。
2. 実装中に「こうした方がよい」と思っても、**コードを先に変えない**。同じ PR で該当ファイルとモックを直し、PR 本文に「画面設計の変更点」を書いてオーナーがレビューする。
3. 各ファイル末尾の **受け入れチェック**を、実装 PR のチェックリストにそのまま貼る。全項目にチェックが付かない PR はマージしない。
4. 数値（サイズ・比率・タップ数・文字数）は本フォルダと [../design-system.md](../design-system.md) の値を使う。コードにマジックナンバーを書かない（`ui-design` ルール）。
5. 本フォルダに無い画面は作らない。必要なら先にファイルを追加し、[../screens.md](../screens.md) のルート表も同じ PR で直す。

このルールは [../../.cursor/rules/development-workflow.mdc](../../.cursor/rules/development-workflow.mdc) と [ui-design.mdc](../../.cursor/rules/ui-design.mdc) に転記済み。

## 1-07 で確定した設計判断（レビュー対象）

| 項目 | 判断 | 理由 |
|---|---|---|
| タブ順 | **ホーム / セラー / 記録 / ノート / 設定**。記録が中央 | オーナー指示（記録が最頻）。中央は円形の primary ボタンとして浮かせる |
| 中央タブの着地 | `/logs`（今日の日別）。日別の最上部に「記録する」＋カメラ＋マイドリンク 1 タップ | どこからでも 2 タップで保存。1 タップで直接 `log-new` を開く案は代替として保留（下記「要確認」） |
| 写真の位置づけ | 記録・ノート・セラーの **作成画面の最上部に写真タイル**。撮る → 編集（比率・色補正・キャラ合成）→ 添付。写真は **任意**（最短タップは維持） | オーナー指示「写真を撮ってそれに記録やコメントを付ける」 |
| セラーの見せ方 | **棚（陳列）**。3 本／段、2:3 の写真が棚板の上に立つ。行リストは廃止 | オーナー指示。写真の切り抜きは v1.x、MVP は比率と色補正 |
| セラーの操作 | **追加**と**消費**の 2 つ。消費 → 貯蔵庫（`/cellar/archive`）へ移り、その日の記録に 1 杯を追加して日別へ遷移 | オーナー指示。開栓はサブ操作として残す |
| 消費の undo | 日別のトースト 5 秒「取り消す」= ボトル復元 + 記録削除 | 誤タップ救済。確認ダイアログは消費ダイアログ自体が担う |
| 1 行 = 1 本 | 登録時の本数 N はサーバーが **N 行に展開**。`quantity` 列は廃止 | 棚に N 本並ぶ。消費は常に 1 本 |
| ボトルステータス | `sealed`（未開栓）/ `opened`（開栓済）/ `consumed`（消費 = 貯蔵庫）。`finished` を `consumed` に改名 | 「飲み切り」より「消費 → 貯蔵庫」の語彙に合わせる |
| 記録とボトルの紐付け | `drink_logs.bottle_id`（任意）。消費で自動、`log-new` の「ボトル」行で手動 | 何を飲んだかを残す。ノートと同じスナップショット方式 |
| ノート一覧 | **写真グリッド 2 列**（4:5）。写真なしは種類アイコンのタイル | 写真主役。文字を写真に重ねない |
| キャラクター | ホーム（覗く）、ログイン、空状態、保存トースト、写真合成。会話はしない | [../character.md](../character.md) |
| モック | 質感確認用。要素表と食い違えば要素表が正 | 画像は差分レビューしにくい |

## 各ファイルの書式（テンプレート）

```
## <画面 ID> <画面名>
| ルート | 親タブ | タブバー | ヘッダー | 主アクション（1 つ） |
目的 / モック画像
レイアウト（箱図）
要素表: # | 要素 | 種別 | 内容・挙動 | データ / API
状態: 初期 / ローディング / 空 / エラー / 成功
操作と遷移: 操作 → 結果（タップ数）
バリデーション（入力がある画面）
キャラクター（出す条件・ポーズ・サイズ）
受け入れチェック（実装 PR に貼る）
```

要素表の「種別」は design-system の部品名（Button 主 / Button 副 / Input / Card / Chip / 行 / 写真タイル / 棚 / Dialog / Toast / Mascot）。
