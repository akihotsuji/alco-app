# モーション・マイクロインタラクション仕様

「動的でアニメーションっぽくてイカしている、でも UI/UX の邪魔にならない」演出を **部分的に** 入れるための正本。画面全体を派手にするのではなく、**使うのが気持ちいい・記録したくなる・状態変化がわかりやすい・キャラクターと世界観が自然に感じられる** ことを目的にする。

- 状態: **オーナー承認済み**（2026-09-06。全項目を採用。D1〜D6・9.6 の「少し凝った」・10.1 の A + B + C・haptic 既定 OFF + 設定スイッチ・11 章 X1〜X8 を含む。同日の中央タブ (c) 確定で **X3 を廃止**し、X1 / X2 / X6 / X7 と M-21 / M-22 の前提を「中央タブは着地しない・1 タップはホームのみ」に合わせて改訂）
- 位置づけ: [design-system.md](design-system.md) の「モーション」節の正本。トークン値は design-system と本ファイルで同じ値を持つ（食い違えば本ファイルが正）。キャラの動きは [character.md](character.md) 6 章、各画面の当てはめは [screen-designs/](screen-designs/README.md) の該当行に `M-xx` で書いてある
- 実装フェーズ: 共通トークンと Button / Chip の `data-state` は **3-02（記録入力）に同梱**、各画面の演出はその画面の実装タスク（3-03 / 3-05 / 3-06 / 3-07 / 4-02 / 4-03 / 4-04 / 5-02）に載せる。単独の「演出フェーズ」は作らない
- 本ファイルの各演出には ID（`M-xx`）を振る。screen-designs から `M-xx` で参照する

## 0. 旧仕様との差分（2026-09-06 承認）

旧正本は「押下 120ms / スコア 150ms / トースト 5 秒 / **それ以外なし**。効果音・バイブは MVP では入れない」（design-system 旧モーション表）。本仕様はこれを **次の 6 点で広げる**（すべて採用）。

| # | 旧 | 新（採用） | 理由 |
|---|---|---|---|
| D1 | 押下は「outset → inset。**拡大しない**」 | 拡大は引き続き禁止。**縮小 0.985（主ボタン・中央タブのみ）+ 下方向 1px** を許可 | 「ほんの少し沈む」感触。影の切替だけでは塗りのある主ボタンに沈み込みが出にくい |
| D2 | 「それ以外なし」 | **状態変化に紐づく 1 回きりの遷移**（行の挿入・ピルの切替・トーストの出入り・週マスの塗り・ダイアログの出入り）を 160〜400ms で許可 | 状態変化の理解を助ける。ループ・待機・装飾目的は引き続き禁止 |
| D3 | キャラは「ポーズのクロスフェード 200ms」のみ | 加えて **≦4px の上下移動 1 回** と、`cheer` の **水面上昇（1 回）** を許可 | 反応があることを最小の動きで示す。表情差分は増やさない（4 ポーズ凍結を維持） |
| D4 | バイブなし | **触感フィードバック（`navigator.vibrate`）を仕様化するが既定 OFF**。設定「触感フィードバック」で ON にできる。iOS Safari は API 非対応のため何も起きない | Android では 10ms の軽い触感が「記録できた」を補強する。iOS で効かないため主導線の理解を触感に依存させない |
| D5 | `?highlight` は「2 秒だけ inset + primary 枠」 | **枠は 2 秒維持したまま、行の挿入と最後の 600ms のフェードアウト** を追加 | いきなり消えると「何が起きたか」が追えない |
| D6 | `prefers-reduced-motion` は「即時切替」 | **移動・拡縮・キーフレームを全て無効**。不透明度のフェード（≦150ms）だけ残す | 完全即時だと状態変化の瞬間が見えず、逆に分かりにくい場面がある（トーストの出現など） |

**変えないもの**: 4 ポーズ凍結、キャラの会話・飲酒助長の禁止、待機ループ禁止、紙吹雪・パララックス禁止、トースト 5 秒、楽観更新なし、白い別面を重ねない。

## 1. 全体コンセプト

> **「静かなグラスに、一杯ぶんだけ波が立つ」**

- 画面は基本 **静止**している。ニューモーフィズムの面は動かない
- ユーザーが何かを **決めた瞬間**（押す・保存する・開栓する）にだけ、その場所で **一度** 小さな反応が起きて、すぐ静まる
- 反応の語彙は 3 つに絞る: **沈む**（押下）、**満たす**（成功・追加）、**開く**（状態の解放）。この 3 語で表せない演出は入れない
- キャラクターは **観客**。主役はユーザーの記録。キャラは成功のときだけ一瞬反応し、指示・催促・待機はしない
- 「満たす」は **ワインの水面**の比喩で統一する（ボタン内の水位、週マスの塗り、キャラの水面）。液体をリアルに描かない。**水平線が 1 本上がる**だけ

## 2. このアプリに合うモーション原則

| # | 原則 | 具体 |
|---|---|---|
| P1 | **1 操作 1 反応** | 1 回のタップで動くものは 1 か所（＋トースト）まで。同時に 3 つ以上を動かさない |
| P2 | **400ms で終わる** | 個別の演出は最長 400ms。連鎖しても 600ms 以内に画面は静止する（トーストの滞在 5 秒は除く） |
| P3 | **触った場所で起きる** | 反応は指の下・その部品の内側で起きる。画面の別の場所が光ったり動いたりしない |
| P4 | **減速で止まる、跳ねない** | イージングは ease-out 系のみ。オーバーシュートは 2% まで。バウンス・弾性は禁止 |
| P5 | **影は移動しない、深さが変わる** | ニューモーフィズムの影は「浮き ↔ 沈み」の深さだけ遷移する。方向・色は変えない。発光（glow）は入れない |
| P6 | **状態が変わるときだけ動く** | 装飾目的・待機中・ループの動きはゼロ。ローディングも静止したスケルトンで、点滅・シマーはしない |
| P7 | **動きがなくても分かる** | 全ての状態変化はテキスト・色・形でも示す。`prefers-reduced-motion` で動きを止めても情報は欠けない |

## 6. デザインシステムとしての共通ルール

承認後は design-system.md の「モーション」節をこの内容に置き換え、トークンを `src/client/styles.css` の `:root` に追加する。

### 6.1 easing

| トークン | 値 | 用途 |
|---|---|---|
| `--ease-out` | `cubic-bezier(0.2, 0, 0, 1)` | 出現・状態変化・戻り。既定 |
| `--ease-in` | `cubic-bezier(0.4, 0, 1, 1)` | 退場（トースト消え、ボタンの退場） |
| `--ease-settle` | `cubic-bezier(0.2, 0.9, 0.3, 1)` | 押下からの戻り。オーバーシュートは 2% 以内 |
| `--ease-fill` | `cubic-bezier(0.3, 0, 0.2, 1)` | 水位線・週マスの満ち。ゆっくり始まり滑らかに止まる |

`ease-in-out`・`linear`（スピナー以外）・`spring` / `bounce` は使わない。

### 6.2 duration

| トークン | 値 | 用途 |
|---|---|---|
| `--dur-press` | 90ms | 押し込み |
| `--dur-release` | 160ms | 押下からの戻り |
| `--dur-state` | 200ms | 状態切替（色・影・不透明度・チップ・ピル・カウント） |
| `--dur-enter` | 240ms | 出現（行・ダイアログ・空状態・グラフ） |
| `--dur-open` | 300ms | 開栓・棚板ハイライト |
| `--dur-fill` | 400ms | 水位線・週マス・キャラの水面 |
| `--dur-blink` | 150ms | キャラのまばたき（M-33） |
| `--dur-gaze` | 240ms | キャラの視線移動（M-34） |
| `--dur-wink` | 380ms | キャラのウィンク（M-35） |
| `--dur-react` | 400ms | 保存反応（M-36） |
| `--dur-fan` | 240ms | 使い方扇メニューの開閉（M-37） |
| `--dur-toast-in` / `--dur-toast-out` | 180ms / 150ms | トーストの出入り |
| `--dur-type-grid-settle` | 180ms | 種類グリッドの着地（M-33） |

上限 400ms。連鎖（stagger）は 1 段 80ms まで。トーストの滞在 5 秒（`TOAST_DURATION_MS`）は別枠。

### 6.3 scale / translate

| 対象 | 値 |
|---|---|
| 主ボタン・中央タブ 押下 | `scale(0.985) translateY(1px)`。**拡大は禁止** |
| 副ボタン・チップ・タブ | scale なし（影の切替のみ） |
| 出現の移動距離 | 6〜12px（行 6px、キャラ 8px、トースト 8px、ダイアログ 12px）。それ以上は動かさない |
| ピルのラベル抜け | 6px |
| キャラの移動 | 上下 4px まで、1 回 |

`transform` と `opacity` だけをアニメーションし、`height` を直接アニメーションしない（行の挿入は `grid-template-rows: 0fr → 1fr` または `max-height` の代替を使う。6.7 参照）。

### 6.4 shadow

- 影は **深さ**だけ遷移する。`--shadow-outset(-sm)` ⇄ `--shadow-inset(-sm)`、`--shadow-primary` ⇄ pressed inset。色・方向・ぼかしの新しい値は作らない
- **outset と inset は `box-shadow` の transition で補間できない**（`inset` キーワードが違うため離散的に切り替わる）。滑らかに見せるときは、部品の `::after`（`inset: 0; border-radius: inherit; box-shadow: var(--shadow-inset-sm); opacity: 0; pointer-events: none`）を重ね、`opacity` を遷移させる
- 発光（外側に色付きのぼかしを広げる）は禁止。棚板ハイライト（M-12）は `--shelf-glass-edge` の 1px 上辺の中を明るい帯が移動するだけで、外へ光らせない
- 塗りのある小部品（週マスの記録あり・中央タブ）に inset を重ねない（既存ルール維持）

### 6.4b 水位線の色（`--fill-tint`）

「満たす」の帯は塗りの上に半透明を重ねるため、**演出中も本文コントラスト 4.5:1 を切らない**値を固定する（WCAG 2.2、計算済み）。

| トークン | ライト | ダーク | 用途 | 演出中のコントラスト |
|---|---|---|---|---|
| `--fill-tint` | `rgba(255,255,255,0.14)` | `rgba(255,255,255,0.14)` | 主ボタン（`--primary` 塗り）の水位線 | `--primary-fg` on 帯: ライト 8.35 → **5.81**、ダーク（`#CC8484`）5.80 → **6.84** |
| `--fill-tint-surface` | `rgba(122,53,56,0.14)`（primary 14%） | `rgba(0,0,0,0.25)` | 地色の部品（チップ・週マス以外）の水位線 | primary 文字 on 帯: ライト 6.68 → **5.39**、ダーク（`#CC8484`）4.96 → **5.63** |

- ダークで `--primary-fg`（暗い文字）14% を重ねるとコントラストが下がる（旧 primary で 4.12）ため、**白 14% に固定**する（暗いボタンが少し明るくなる方向）
- ダークの地色チップは白を重ねると primary 文字（明るい）とのコントラストが下がるため、**黒 25%** で暗くする方向にする
- 帯は文字の背後にだけ置き、文字自体の色・不透明度は変えない

### 6.5 haptic feedback

| 項目 | 値 |
|---|---|
| API | `navigator.vibrate(pattern)`。ラッパー `src/client/lib/haptic.ts` の `haptic(kind)` だけを呼ぶ。未対応（iOS Safari、`vibrate` 無し）では no-op |
| 種別 | `light` = `[10]`（押下・チップ選択）、`success` = `[10, 40, 10]`（保存・開栓・復元の成功）。`error` は **無し**（エラーは文言で伝える。振動で不安にさせない） |
| 既定 | **OFF**。設定 `settings` に「触感フィードバック」スイッチ（`localStorage` `ui.haptic`）。ON にした端末でのみ動く |
| 併用条件 | `prefers-reduced-motion: reduce` でも設定 ON なら振動する（動きと触感は独立） |
| 禁止 | 100ms を超えるパターン、連続 2 回以上、失敗時、キャラの動きに同期させる |

iOS は Vibration API 非対応のため、主導線の理解を触感に依存させない（P7）。設定画面の文言は「対応端末（Android）で有効」を添える。

### 6.6 character usage

| ルール | 値 |
|---|---|
| 動く条件 | 保存成功、登場時の視線、短い待機まばたき、タップ／完了のウィンク、多量プレビューの傾き。入力中の装飾ループはしない |
| 許可する動き | 既存のクロスフェード / 4px 上下 / `cheer` 水面に加え、まばたき（`--dur-blink`）、視線（`--dur-gaze`）、ウィンク（`--dur-wink`）。多量は傾きとしずくを 1 回 |
| 禁止 | 待機の揺れ・ジャンプ、口や手足、2 体同時、連打で動きを積む、液体が文字やボタンを隠す、飲み過ぎの独自閾値 |
| 頻度 | 待機まばたきは 15〜30 秒。タップはクールダウン。同じ画面で動くキャラは 1 体 |
| 実装 | `<Mascot pose size pour life />`。画面外・非表示・reduced motion で停止。`pour` は `cheer` のときだけ |

### 6.7 実装の共通方針（画面構造を壊さない）

- **ライブラリを足さない**。CSS transition / `@keyframes` と最小の Web Animations API（数字のカウント）だけ。framer-motion 等は導入しない（バンドル + 設計との二重管理）
- 状態は **`data-state` 属性**で表す（`idle | pressed | loading | success | error`）。CSS はそれに反応する。React 側は状態を置くだけで、アニメーションの制御をしない
- DOM 構造は変えない。疑似要素（`::before` 水位線、`::after` 影の重ね）で描く
- 「1 回だけ」の演出は **`sessionStorage` または React の ref** で再生済みを記録する（M-19 / M-26。M-03 は廃止）
- `useReducedMotion()` フック（`src/client/hooks/use-reduced-motion.ts`）を 1 か所に置き、**OS の `prefers-reduced-motion: reduce` または設定「動きを減らす = 常に減らす」（`ui.reduce-motion`、06-settings S9）のどちらかで true**。`scrollIntoView` の `behavior` や `pour` の有無など JS 側の分岐に使う。CSS 側は `AppShell` が `<html data-reduce-motion="1">` を付け外しし、その属性で一括無効化する（メディアクエリと設定を 1 つのセレクタに集約するため。テーマの `.dark` 固定禁止とは別の話で、これは OS 設定を上書きする逃げ道）
- 行の挿入は `height` をアニメーションせず、外側ラッパーの `grid-template-rows: 0fr → 1fr`（対応ブラウザ）で行う。非対応環境は不透明度のフェードだけ
- 全てのトークンは `styles.css` の `:root` に置き、`bg-[...]` と同様に **その場の `duration-[...]` / `ease-[...]` は禁止**（`ui-design` ルールに追記）

### 6.8 reduced motion（共通）

```css
/* AppShell が OS の prefers-reduced-motion または設定「常に減らす」で付ける */
html[data-reduce-motion="1"] *,
html[data-reduce-motion="1"] *::before,
html[data-reduce-motion="1"] *::after {
  animation-duration: 0.01ms !important;
  animation-iteration-count: 1 !important;
  transition-duration: 0.01ms !important;
}
/* 不透明度のフェードだけは残す（状態変化の瞬間を見失わないため） */
html[data-reduce-motion="1"] .app-toast,
html[data-reduce-motion="1"] .skeleton-fade,
html[data-reduce-motion="1"] .log-row-enter {
  transition-property: opacity;
  transition-duration: var(--dur-toast-out);
}
```

- 移動・拡縮・水位線・棚板ハイライト・キャラの動きは **全て無し**
- 残すのは不透明度のフェード（≦150ms）と、色・影の即時切替
- `?highlight` のリングは 2 秒静止したのち即時消える
- `scrollIntoView` は `behavior: "auto"`

## 8. 主ボタンの押下（`M-01` / `M-02`）

前提: ベージュの地、ワインレッドの塗り（`--primary`）+ `--shadow-primary`、高さ 52px、角 `--radius`。ホームの「お酒を記録する」（H8）は 2026-09-08 に廃止。押下の沈みは主ボタンと中央タブ（`M-21`）が共有する。loading / success を持つのは `log-new` の「保存する」（M-04〜M-06）と、その場で保存が完了するマイドリンクチップ（M-07〜M-08）。

### 8.1 状態

| 状態 | 見た目 | 備考 |
|---|---|---|
| 通常（idle） | `--primary` 塗り、`--shadow-primary`、文字 `--primary-fg` 600 | 静止。光らない・脈動しない |
| pressed | `scale(0.985) translateY(1px)`、影 → `inset 3px 3px 6px rgba(0,0,0,0.25)`（`::after` の不透明度 1）、明度 0.92 | 指の下で 1px 沈み、影が消えて「地に付く」 |
| loading（保存ボタンのみ） | ラベル「保存中」、`disabled`、水位線が下端から 1 回上がる | スピナー無し。満水で静止 |
| success（保存ボタンのみ） | **表示しない**。2xx で即遷移 | 成功は到着先（行挿入 + トースト）が示す |
| success（チップのみ） | 水位線 1 回 + inset → outset 復帰 | 遷移しない場面の成功表示 |
| disabled | 既存（不透明 0.6）。影は `--shadow-primary` のまま | 未来日など |

### 8.2 アニメーションの流れ（中央タブで押した場合）

```
0ms     pointerdown   → scale 0.985 / translateY 1px / 影 inset / 明度 0.92   (90ms, ease-out)
~90ms   [沈んだまま]                                                          指が触れている間
pointerup             → 元へ戻る (160ms, ease-settle。2% 以内の行き過ぎ)
同時                  → navigate("/logs/new")                                 戻りを待たない
```

`log-new` の「保存する」で押した場合:

```
0ms     pointerdown → 沈む (90ms)
pointerup           → 戻る (160ms) と同時に POST 開始 → data-state="loading"
0〜400ms            水位線が下端から上へ (400ms, ease-fill)。ラベル「保存中」
2xx                 → 即 navigate("/logs/<date>?highlight=<id>")。ボタンは何もしない

非 2xx              → 水位線フェードアウト (200ms)、ラベル復帰、インライン汎用文
```

| 項目 | 値 |
|---|---|
| press duration / easing | `--dur-press` 90ms / `--ease-out` |
| release duration / easing | `--dur-release` 160ms / `--ease-settle` |
| scale | 0.985（縮小のみ） |
| translate | Y 1px |
| shadow idle | `--shadow-primary` |
| shadow pressed | `inset 3px 3px 6px rgba(0,0,0,0.25)`（既存 `shadow-primary-pressed`） |
| brightness pressed | 0.92 |
| 水位線 | `::before`、`inset: 0`、`background: var(--fill-tint)`、`transform-origin: bottom`、`scaleY 0→1`、`--dur-fill` 400ms `--ease-fill`、`border-radius: inherit`、`overflow: hidden` を親に |

### 8.4 haptic

| タイミング | 種別 |
|---|---|
| 保存 2xx / チップ 2xx | `success`（10, 40, 10） |
| 失敗 | 無し |

既定 OFF、設定で ON（6.5）。

### 8.5 キャラクターの最小演出

- 中央タブ押下では **キャラは動かさない**（P3: 触った場所で起きる。カードのキャラは指から遠い）
- 1 タップ記録（チップ）の成功では、既存仕様の `cheer` 300ms → `default` に加え、切替の瞬間に **上 4px → 0**（`--dur-state`）を 1 回。水面上昇は同時に行わない（トーストの `cheer` が担う。同時に 2 か所で水面を上げない）
- 記録 0 → 1 で `rest` → `default` のクロスフェード（既存 200ms）

### 8.6 実装方針（画面構造を壊さない）

- `Button` の `default` variant に `data-state` 属性と `::before` / `::after` を追加する
- `active:` の Tailwind ユーティリティを、`data-state="pressed"` ではなく引き続き `:active` で扱う（JS で pressed を管理しない）。`transform` を transition プロパティに足す
- loading は `useMutation` の `isPending` を `data-state` に写す。success は状態を置かない（即遷移）
- `haptic()` は `onPointerUp` ではなく mutation の `onSuccess` で呼ぶ（キャンセルされたタップに振動させない）

## 9. セラー詳細「開栓する」の詳細設計

前提（2026-09-06 のセラー改訂 #28）: 棚の本はすべて `sealed`。**「開栓する」は 1 本を貯蔵庫（`consumed`）へ移す**主ボタンで、確認ダイアログも 1 杯の記録も無い。成功で `/cellar` へ戻り、トースト「開栓しました  取り消す」（undo = `restore`）。したがって「未開栓 → 開栓済み」の変化は詳細画面のピルでは起きず、**棚から 1 本が抜ける**ことで表れる。演出はそこに置く。

### 9.1 視覚メタファーの選定

| 候補 | 判断 | 理由 |
|---|---|---|
| コルク | 不採用 | リアルなコルクは禁止条件。ピルの切替が無くなったため「抜ける」動きを借りる場所も無い |
| キャップ | 不採用 | ワイン以外（ビール缶・一升瓶）に合わない。種類を問わない表現が必要 |
| ラベル | 不採用 | ラベルは銘柄の顔。動かすとボトルが別物に見える |
| 液体 | **棚板ハイライトで間接的に採用** | ボトルの中身は写真なので動かせない。本があった段の棚板の上辺を一瞬明るくして「その本の周りで何か起きた」を示す |
| 開く / 解放される | **主メタファー** | 開栓 = 棚（保管）から解放されて貯蔵庫へ移る。**本数が 1 つ減る**（数字のカウント）と **段が空く**（棚板ハイライト）の 2 つで「抜けた」を表す。取り消しは **置かれる**（上 6px から降りて現れる） |

### 9.2 状態遷移

| 状態 | 「開栓する」T3（詳細） | `/cellar`（到着先） | その他 |

| 実行中（`POST consume` 送信中） | ラベル「更新中…」、`disabled`、水位線が下から 1 回上がる（M-04） | — | 確認ダイアログは出さない |
| 完了（2xx） | **即** `/cellar` へ（M-05。ボタン側の成功表示は無し） | M-10: ヘッダー「セラー N 本」が N → N−1 にカウント、抜けた段の棚板に明帯が 1 回。隣の本は再描画で詰まる | トースト「開栓しました  取り消す」（`cheer` + M-25）、haptic `success` |

## 10. 飲酒ログ追加時の成功フィードバックの詳細設計

条件: 0.4〜1.2 秒で終わる、視認性が高い、情報の邪魔をしない、キャラは補助、1 日に何度も見ても鬱陶しくない、トースト / スナックバー / カード挿入の組み合わせ。

### 10.1 ベストな成功演出 3 案

| 案 | 名前 | 構成 | 合計時間 | UX 上の狙い |
|---|---|---|---|---|
| **A（推奨）** | **一杯が並ぶ** | 到着先 `log-day` で新しい行が **その位置に挿入**され（M-14）、primary リングが 2 秒残って最後にフェード（M-15）。同時にトーストが下から出て（M-23）、`cheer` の水面が上がる（M-25） | 見た目の動き 400ms（行 240 + トースト 180 並行）、リング 2 秒は静止 | 「何が・どこに」加わったかを **一覧そのもの**で示す。トーストは undo の入口として脇役 |
| **B** | **今日が満ちる** | ホーム / 日別の合計スコアが旧 → 新へカウント（M-09）、未記録ピルがフェードアウト、今週の今日印が下から満ちる（M-17）。トーストは A と同じ | 400ms | 「今日という器が 1 杯ぶん埋まった」。1 タップ記録（遷移なし）に最適 |
| **C** | **グラスに注がれる** | トーストのみで完結。`cheer` 32px の水面が 45% → 60% に上がり（M-25）、その 80ms 後に文言「記録しました」がフェードイン。一覧側は既存のハイライトのみ | 480ms | 最小構成。キャラが「受け取った」ことだけを示す。他 2 案の部品でもある |

**採用（2026-09-06）**: 保存（`log-new` → `log-day`）は **A**、1 タップ記録（ホームで遷移なし）は **B**、両方に **C** のトーストを共通で添える。3 案は排他ではなく、A/B は「到着先」の違い、C はその共通部品。1 タップ記録はホームだけで起きる（日別のチップは同日の中央タブ (c) 確定で廃止）ため、**A の行挿入を伴う 1 タップは無い**。保存後の日別で「取り消す」を押したときは、消える行を inset → フェードアウト（X2）し、合計をカウントで戻す（M-09）。

### 10.2 ログ一覧への追加のされ方（A の詳細）

```
到着 (log-day?highlight=<id>)
  0ms   一覧を描画。該当行のラッパーは grid-template-rows: 0fr、行は opacity 0 / translateY(6px)
  0ms   該当行が画面外なら scrollIntoView({ block: "center", behavior: "smooth" })   (M-16)

        → 他の行は自然に押し下げられる（並び順は drunkAt 降順のまま）

256ms   行に inset + primary 2px リング（既存）                                        (M-15)
~1.66s  リングを 600ms でフェードアウト
```

- 行は **一覧の正しい位置**に入る（先頭に割り込ませて後で並び替える、はしない）
- 挿入中も他の行はタップできる（`pointer-events` を止めない）
- 一覧が空だった場合（0 → 1 件）: 「この日の記録はまだありません」を `--dur-state` でフェードアウトしてから行を挿入。合計「休肝」ピルは M-18 でフェードアウト
- `?highlight=` は挿入後に `history.replaceState` で URL から除く（リロードで再演出しない）

### 10.3 キャラクターの使い方

- **トーストの `cheer` 32px のみ**。位置・サイズは既存仕様のまま
- 動きは水面上昇 1 回（M-25）。目・星・輪郭は動かさない

- 文言は既存の「記録しました  取り消す」のみ。「N 杯目」「乾杯」等は出さない

| 部品 | 変更 |

### 10.5 アクセシビリティ上の注意

- トーストは `role="status" aria-live="polite"`（既存）。動きに関係なく読み上げられる。挿入行には `aria-live` を **付けない**（二重読み上げ）
- 「取り消す」は 6 秒間ずっと押せる。演出中も `disabled` にしない。タップ領域 44px を保つ。操作せず離れたら残り時間を再開する。明示的に「閉じる」できる
- 文字をアニメーションしない（水位線はラベルの背後、ラベル自体は動かさない）。コントラスト 4.5:1 を演出中も維持する（`--fill-tint` で `--primary-fg` on `--primary` はライト 5.81 / ダーク 6.84。6.4b で計算済み）
- 点滅しない（1 秒に 3 回以上の明滅を作らない）。リングは 1 回消えるだけ
- フォーカス: 保存後の到着先ではフォーカスを **ヘッダーの日付**に置く（新しい行に強制移動させない。スクリーンリーダー利用者はトーストの読み上げで完了を知る）
- ハイライト行はリングに加えて `aria-describedby` 等は付けない（視覚的な一時強調であり、意味情報ではない）
