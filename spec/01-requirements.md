# 要件定義

MVP（最初にリリースする最小構成）と、その後の拡張（v1.x）を分けて定義する。
各機能の詳細仕様（画面項目・バリデーション等）は、実装フェーズ開始時に `spec/features/` 配下に個別ドキュメントとして起こす。

## 1. 機能要件

### 1.1 アカウント・認証【MVP】

- メールアドレス＋パスワードでのサインアップ / ログイン / ログアウト
- **招待制は採用しない**（招待コード・登録クローズフラグは作らない）
- 将来の一般公開を見据え、全データはユーザーIDに紐づける（マルチテナント設計）
- 個人利用フェーズではアプリURLを公開しない運用で、不特定多数の登録を防ぐ
- 【v1.x】Google等のOAuthログイン、パスワードリセットメール。一般公開時はレート制限等でオープン登録に耐える（Phase 8）

### 1.2 飲酒記録【MVP・最優先】

毎日使う機能のため、**最短タップ数で記録できること**を最重要のUX要件とする。

- 記録単位: 1杯（グラス/ショット/缶など）。以下を記録する
  - 酒の種類（ワイン/ビール/ウイスキー/日本酒/焼酎/カクテル/その他）
  - 量（ml）とアルコール度数（%）。種類選択時に下表の一般的な量・度数をデフォルト投入し、**記録ごとに修正できる**
  - 日時（デフォルトは現在時刻。日の帰属は Asia/Tokyo）、任意メモ
- 種類ごとのデフォルト（2026-08-13 確定。保存されるのはその記録の値。種類デフォルトの変更は過去ログに影響しない）

  | 種類 | デフォルト量 | デフォルト度数 | 目安 |
  | --- | ---: | ---: | --- |
  | ワイン | 125ml | 12% | グラス1杯 |
  | ビール | 350ml | 5% | 缶1本 |
  | ウイスキー | 30ml | 40% | ショット |
  | 日本酒 | 180ml | 15% | 1合 |
  | 焼酎 | 60ml | 25% | 水割り・ロックの原酒1杯 |
  | カクテル | 120ml | 15% | ショートカクテル1杯 |
  | その他 | （手入力必須） | （手入力必須） | デフォルトなし |

- 純アルコール量（g）の自動計算: `量(ml) × 度数(%) / 100 × 0.8`
- 丸め・入力上限・休肝日の定義の正本は [features/alcohol-calculation.md](features/alcohol-calculation.md)
- 日次集計・休肝日判定の日付境界は **Asia/Tokyo**。日時の保存は UTC
- よく飲む組み合わせを「マイドリンク」としてプリセット登録し、1タップで記録できる
- **写真を 1 枚添えられる**（任意。撮る → 比率 4:5 に切る → 色補正 → キャラクター合成 → 保存。最短タップ数は写真なしの経路で守る。2026-09-05）
- セラーのボトルに紐づけられる（任意。消費からの自動作成、または記録入力で選択）
- サマリー表示
  - 日別: その日の杯数・純アルコール量
  - 週別/月別: 推移グラフ、休肝日数
- 【v1.x】目標設定（週あたり純アルコール量上限、休肝日目標）と達成状況表示

### 1.3 セラー管理【MVP】

- ボトルの登録・編集・削除
  - 銘柄名、種類、生産者、産地、ヴィンテージ/年、購入日、購入価格、購入場所、写真、保管場所、メモ
  - 登録時に本数を指定でき、**1 本 = 1 行**として棚に並ぶ（同じ属性で N 行。上限 12。2026-09-05）
- **棚（陳列）で見せる**: 地色の上に **ガラス風の棚板**を置き、**背景を除去して切り抜いた**ボトルを 3 本ずつ立てる（切り抜きは端末内。できないときは 2:3 の長方形写真）。写真が無いボトルは種類別のシルエット
- **表示切替**: 「種類ごと」（種類名の見出し + 横スクロール 1 段）と「1 本ずつ」（3 列）を切り替えられる（2026-09-05）
- **ラベルの AI 読み取り**: 登録時にラベル写真から銘柄名・生産者・産地・年・種類・度数の候補を取得し、空欄に入れる（Cloudflare Workers AI。セラーのみ。自動保存はしない。設定で OFF 可。2026-09-05）
- 操作は **追加**と**消費**の 2 つ。消費したボトルは **貯蔵庫（アーカイブ）** に移る。開栓はサブ操作
  - ステータス: 未開栓 / 開栓済み（棚）/ 消費（貯蔵庫）。復元（貯蔵庫 → 棚）可
- **消費 → その日の記録**: 消費時に「今日の記録に 1 杯を追加」（既定 ON）でき、保存後はその日の日別記録へ遷移する。取り消しはトースト 5 秒（2026-09-05）
- 一覧表示: 種類・ステータスでの絞り込み、名前・生産者での検索。貯蔵庫は月ごと
- 写真アップロード（クライアント側で切り抜き・リサイズ・色補正してから保存）
- 【v1.x】飲み頃メモ・アラート、在庫金額サマリー、Gemini 等の外部 Vision API への差し替え、記録・ノート写真の AI 推定

### 1.4 テイスティングノート【MVP】

- ノートの作成・編集・削除
  - **写真を撮って、評価と一言を付ける**体験を第一にする（写真は任意、最大 6 枚。キャラクター合成可。2026-09-05）
  - 対象銘柄（セラーのボトル（貯蔵庫含む）から選択 or 都度入力）、飲んだ日
  - 外観 / 香り / 味わい / 余韻 のフリーテキスト（「一言」は味わい欄の 1 行表示）
  - 総合評価（5段階 x.5刻み）
- 一覧は **写真グリッド**。銘柄名・種類・評価での絞り込み
- セラーのボトル詳細から、そのボトルのノート一覧を参照できる
- 【v1.x】種類別の評価テンプレート（ワイン用・ウイスキー用の評価軸プリセット）

### 1.5 機能間の連携

- 【MVP】セラーの「消費」でその日の飲酒記録を 1 件作成し、日別記録へ遷移する（1.3。2026-09-05 に v1.x から繰り上げ）
- 【MVP】飲酒記録・ノートからセラーのボトルを選んで紐づける
- 【v1.x】テイスティングノート作成時に飲酒記録を同時作成

### 1.6 キャラクターと写真体験【MVP】（2026-09-05 追加）

- **1 体のキャラクター**（赤ワインの入ったワイングラスに目が付いたマスコット。[character.md](character.md)）でポップさを足す。ホーム・ログイン・空状態・保存トーストに出す。会話はしない。飲酒を促す文言に添えない
- 記録・ノートの写真は、右下にキャラクター（驚きポーズ）を合成できる（既定 ON、保存前に OFF 可）。セラー写真には合成しない
- 写真の加工（切り抜き・リサイズ・色補正・合成）は **すべて端末内**で行い、加工後の 1 枚だけ保存する

## 2. 非機能要件

| 項目           | 要件                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------ |
| 対応デバイス   | スマートフォン（iOS Safari / Android Chrome）を第一とする。PCブラウザでも崩れない程度に対応      |
| UIテーマ       | 端末・OSの外観設定に追従（ライト／ダーク両方。アプリ内切替は持たない）                           |
| タイムゾーン   | 日付境界・カレンダー日・休肝日は Asia/Tokyo。保存は UTC                                         |
| PWA            | ホーム画面追加、スタンドアロン表示、アプリアイコン、スプラッシュ。オフライン動作は対象外         |
| パフォーマンス | 初回表示3秒以内（4G想定）、記録操作のレスポンス1秒以内                                           |
| セキュリティ   | 全通信HTTPS、パスワードハッシュ化、全APIで認証・認可チェック（他ユーザーのデータへアクセス不可） |
| 可用性         | 個人利用フェーズではベストエフォート。データ消失を防ぐことを最優先（日次バックアップ）           |
| コスト         | 無料枠内での運用（独自ドメイン代を除く）                                                         |
| 保守性         | 型安全（TypeScript strict）、自動テスト、CI、スキーマ駆動のAPI、ドキュメントとコードの同期       |
| 法令対応       | 一般公開時に20歳以上の年齢確認、利用規約・プライバシーポリシーを整備（個人利用フェーズでは不要） |

## 3. 将来構想（設計時に考慮のみしておく）

- 一般公開（不特定多数のユーザー登録）
- 飲酒量データのエクスポート（CSV）
- 統計の充実（種類別の消費傾向、支出推移）
- ラベル読み取りの外部 Vision API（Gemini 等）への差し替え、記録・ノート写真からの種類・度数推定（2026-09-04 の「セラー風の背景」と切り抜きは 2026-09-05 に MVP 化）
