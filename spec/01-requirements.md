# 要件定義

MVP（最初にリリースする最小構成）と、その後の拡張（v1.x）を分けて定義する。
各機能の詳細仕様（画面項目・バリデーション等）は、実装フェーズ開始時に `spec/features/` 配下に個別ドキュメントとして起こす。

## 1. 機能要件

### 1.1 アカウント・認証【MVP】

- メールアドレス＋パスワードでのサインアップ / ログイン / ログアウト
- 将来の一般公開を見据え、全データはユーザーIDに紐づける（マルチテナント設計）
- 個人利用フェーズでは新規登録を招待制（環境変数等で制御）にできること
- 【v1.x】Google等のOAuthログイン、パスワードリセットメール

### 1.2 飲酒記録【MVP・最優先】

毎日使う機能のため、**最短タップ数で記録できること**を最重要のUX要件とする。

- 記録単位: 1杯（グラス/ショット/缶など）。以下を記録する
  - 酒の種類（ワイン/ビール/ウイスキー/日本酒/焼酎/カクテル/その他）
  - 量（ml。種類ごとの標準量をプリセット: ワイン125ml、ビール350ml、ショット30ml等）
  - アルコール度数（種類ごとのデフォルト値を編集可能）
  - 日時（デフォルトは現在時刻）、任意メモ
- 純アルコール量（g）の自動計算: `量(ml) × 度数(%) / 100 × 0.8`
- よく飲む組み合わせを「マイドリンク」としてプリセット登録し、1タップで記録できる
- サマリー表示
  - 日別: その日の杯数・純アルコール量
  - 週別/月別: 推移グラフ、休肝日数
- 【v1.x】目標設定（週あたり純アルコール量上限、休肝日目標）と達成状況表示

### 1.3 セラー管理【MVP】

- ボトルの登録・編集・削除
  - 銘柄名、種類、生産者、産地、ヴィンテージ/年、購入日、購入価格、購入場所、本数、写真、保管場所、メモ
- ステータス管理: 未開栓 / 開栓済み / 飲み切り
- 一覧表示: 種類・ステータスでの絞り込み、名前・生産者での検索
- 写真アップロード（クライアント側でリサイズしてから保存）
- 【v1.x】飲み頃メモ・アラート、在庫金額サマリー

### 1.4 テイスティングノート【MVP】

- ノートの作成・編集・削除
  - 対象銘柄（セラーのボトルから選択 or 都度入力）、飲んだ日
  - 外観 / 香り / 味わい / 余韻 のフリーテキスト
  - 総合評価（5段階 x.5刻み）
  - 写真（複数枚）
- 一覧・検索: 銘柄名・種類・評価での絞り込み
- セラーのボトル詳細から、そのボトルのノート一覧を参照できる
- 【v1.x】種類別の評価テンプレート（ワイン用・ウイスキー用の評価軸プリセット）

### 1.5 機能間の連携【v1.x】

- セラーのボトルを「開栓」した際に、飲酒記録・テイスティングノートの作成へ誘導
- テイスティングノート作成時に飲酒記録を同時作成

## 2. 非機能要件

| 項目 | 要件 |
|---|---|
| 対応デバイス | スマートフォン（iOS Safari / Android Chrome）を第一とする。PCブラウザでも崩れない程度に対応 |
| PWA | ホーム画面追加、スタンドアロン表示、アプリアイコン、スプラッシュ。オフライン動作は対象外 |
| パフォーマンス | 初回表示3秒以内（4G想定）、記録操作のレスポンス1秒以内 |
| セキュリティ | 全通信HTTPS、パスワードハッシュ化、全APIで認証・認可チェック（他ユーザーのデータへアクセス不可） |
| 可用性 | 個人利用フェーズではベストエフォート。データ消失を防ぐことを最優先（日次バックアップ） |
| コスト | 無料枠内での運用（独自ドメイン代を除く） |
| 保守性 | 型安全（TypeScript strict）、自動テスト、CI、スキーマ駆動のAPI、ドキュメントとコードの同期 |
| 法令対応 | 一般公開時に20歳以上の年齢確認、利用規約・プライバシーポリシーを整備（個人利用フェーズでは不要） |

## 3. 将来構想（設計時に考慮のみしておく）

- 一般公開（不特定多数のユーザー登録）
- 飲酒量データのエクスポート（CSV）
- 統計の充実（種類別の消費傾向、支出推移）
